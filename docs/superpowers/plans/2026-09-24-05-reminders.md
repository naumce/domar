# Domar Reminders and Email Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A building manager presses one button (or lets cron press it) and every owner who is two consecutive periods or three periods behind gets a legally correct Art. 28 reminder — emailed with the letter attached as a PDF when the owner has an email address, queued as a printable letter when they do not — with the rendered document, the delivery attempt and its outcome stored as evidence. The same mailer lets the manager email a single invoice or a whole published period.

**Architecture:** `@domar/domain` gains a pure `reminders/evaluate.ts` (`evaluateOwner`) and two new `CountryLabels` entries (`reminderIntro`, `reminderLegal`). `@domar/db` gains migration `0005` with `reminders` and `email_log`. `apps/api` gains `src/email/{mailer.ts,log.ts,invoice-send.ts,routes.ts}` (nodemailer wrapped so an unset `SMTP_URL` is a logged no-op), `src/pdf/reminder-html.ts`, and `src/resources/reminders/{schema,repo,service,routes}.ts` with the building run endpoint, the reminder list/PDF/printed endpoints and the unauthenticated `POST /api/jobs/reminders` guarded by `x-job-token`. `apps/web` gains a "Reminders" building tab, a "Send by email" button on the invoice page, a bulk send button on the period page and an email-status line on the settings page. Dev compose gains `mailpit`; `docs/DEPLOY.md` documents the host crontab that calls the job.

**Tech Stack:** unchanged (Node 24, pnpm 10, TS strict, Fastify 5 + zod, Drizzle + Postgres 16, Vue 3 + Vite + vue-i18n + Tailwind 4, Vitest, Playwright 1.63.0). New runtime dependency: `nodemailer` (API), plus `@types/nodemailer` as a devDependency.

**Spec:** `docs/superpowers/specs/2026-09-21-domar-phase1-design.md` §18 (the eight points of this sub-plan), §9 (the Art. 28 rule), §7 (ledger — untouched here: a reminder books nothing), §10 (auth and tenancy), §11 (API shape), §12 (web), §13 (PDF), §16 (global constraints). Project conventions that are equally binding here:

- **Money is integer minor units** everywhere (`number` in TS, `bigint` in Postgres). Amounts on the wire end in `Minor`. `totalOutstandingMinor` on a reminder is the sum of the covered invoices' outstanding amounts and is always positive.
- **Tenant filter on every statement**, including correlated subqueries and every `and(...)` in a repo. Nothing is fetched by id alone; the id is always paired with `eq(table.tenantId, ctx.tenantId)`.
- **An audit row is written inside the same transaction as every mutation** (`writeAudit(tx, ctx, …)`), never after it and never outside it. Audit payloads never contain a password hash and never contain a rendered document.
- **Role gating:** writes use `preHandler: requireRole(...WRITE_ROLES)` (`owner`, `accountant`); reads only need `app.requireAuth`. The single exception is `POST /api/jobs/reminders`, which has no session at all and is guarded by the `x-job-token` header (design addendum 9).
- **Error envelope:** `{ error: { code, message, details? } }` produced by `AppError`/`notFound`/`badRequest`/`conflict`/`unauthorized`/`forbidden` and the handler in `app.ts`. New codes in this plan: `no_email`, `invoice_not_sendable`, `not_pending`, `job_token_not_configured`.
- **Claim-first `UPDATE … RETURNING` for state transitions.** `POST /reminders/:id/printed` claims the row with `where status = 'pending' and channel = 'letter'` and answers `409 not_pending` when nothing comes back.
- **TS strict with `exactOptionalPropertyTypes`**: never pass an explicit `undefined` into an object typed with an optional property unless the property type includes `| undefined`; use `stripUndefined()` before drizzle `.set()`/`.values()` spreads, and spread conditionally (`...(x ? { x } : {})`) when building optional fields.

## Design addendum (decisions not spelled out in the spec)

1. **`evaluateOwner(input, rules, today)` takes one owner's invoices and that owner's prior reminders, and returns `{ due, reason, invoiceIds }`.** When `due` is `false`, `reason` is `null` and `invoiceIds` is `[]` — a caller never has to distinguish "not due" from "due but empty". `invoiceIds` is the **sorted** list of every overdue invoice with a positive outstanding amount, so the same debt always produces the same set regardless of query order.
2. **Overdue means `outstandingMinor > 0` and `Date.parse(dueAt) < today.getTime()`.** `dueAt` is an ISO string on the pure boundary (`packages/domain` must not depend on `Date` construction rules); the API passes `invoice.dueAt.toISOString()`.
3. **"Consecutive" is the longest run of consecutive *distinct periods*** among the overdue invoices, stepped with the existing `nextPeriod`; "total" is the count of distinct overdue periods. Periods are sorted with the existing `comparePeriods`. Consecutive is tested first, so with the `mk` rules (2 / 3) a three-in-a-row debt reports `consecutive`, not `total`.
4. **Suppression: a new reminder is refused when a prior reminder's `sentAt` is less than 30 days before `today` *and* the new invoice set is a subset of that prior reminder's set.** Strictly less than 30 days: a reminder sent exactly 30 days ago no longer suppresses. Subset rather than equality is what makes the rule useful — the same two unpaid invoices are suppressed, but a third unpaid period makes the new set larger, so it is no longer a subset and a fresh reminder goes out.
5. **The API treats a created-but-unsent reminder as sent for suppression purposes**: `PriorReminder.sentAt` is `reminder.sentAt ?? reminder.createdAt`. Without this a `pending` letter or a `failed` email would regenerate a duplicate reminder every night.
6. **`feeAllowed: false` is enforced by omission and locked by tests.** No code path in this plan computes, books or renders a fee; `reminder-html.ts` has no fee row, the reminder writes no posting, and `packages/domain/test/reminders.test.ts` asserts `mkPack.reminderRules.feeAllowed === false` while `apps/api/test/reminders.test.ts` asserts the rendered document contains no fee wording.
7. **`email_log.to` is stored in the column `to_address`.** `TO` is a reserved SQL keyword; the drizzle field stays `toAddress` and the API field on the wire is `to`.
8. **The `email_log` row for a reminder is written in the *post-send* transaction, together with the reminder's status update and a `reminder.send` audit row.** §18.5 says the log row is written "inside the reminder transaction" and §18.8 says sending happens after that transaction commits; both cannot be true of the same transaction. The invariant that actually matters (§18.8) is that no row is written without an audit row in the same transaction, so the run is two transactions: (a) insert reminders + `reminder.create` audit, commit; (b) per reminder, send, then update the reminder + insert the `email_log` row + `reminder.send` audit, commit. A failed send never rolls back the reminder.
9. **`POST /api/jobs/reminders` has no session.** Missing or empty `x-job-token` → `401 unauthorized`; present but wrong → `403 forbidden`; `JOB_TOKEN` unset on the server → `503 job_token_not_configured`. The comparison is `crypto.timingSafeEqual` over UTF-8 buffers after a length check. The route carries its own rate limit (`max: 6, timeWindow: '1 minute'`).
10. **`JOB_TOKEN` is required when `NODE_ENV=production`** and enforced in `config.ts` with a `superRefine`, so a production container without it fails to boot rather than silently never sending reminders.
11. **The test transport is nodemailer's `jsonTransport`, selected by the literal config value `SMTP_URL=json`**, and the mailer keeps every message it sent through that transport in `mailer.outbox`. A real SMTP transport never fills `outbox`, so a long-lived production process accumulates nothing. Vitest builds its app with `createTestApp({ SMTP_URL: 'json' })`; no test opens a socket.
12. **`TenantContext.userId` widens to `string | null`.** The nightly job has no user, and `audit_logs.user_id` is already nullable with no foreign key. The only call site that needs a non-null user is `changeOwnPassword` in `resources/users/repo.ts`, which is only reachable behind `requireAuth` and therefore asserts it once with `!`.
13. **`publishPeriod` accepts an optional `dueAt`.** The only way to produce an overdue invoice today is to publish with a due date in the past, and neither `periodCreate` nor `periodPatch` carries `dueAt`. `POST /buildings/:buildingId/periods/:id/publish` therefore takes the optional body `{ dueAt?: ISO datetime }`, defaulting to the existing `issued + 15 days`. This is what the API tests and the e2e spec use to backdate; no test writes `due_at` with raw SQL.
14. **The bulk send route is `POST /api/buildings/:buildingId/periods/:id/send`.** §18.6 writes `:periodId`, but the existing routes registered under the `/buildings/:buildingId/periods` prefix already use `:id`, and Fastify refuses two different parameter names on the same path segment. The URL shape is identical.
15. **An invoice can be emailed while it is `published`, `partially_paid` or `paid`** (a receipt copy is legitimate); `draft` and `cancelled` answer `409 invoice_not_sendable`. A contact without an email answers `409 no_email`. The bulk route never fails on a single owner: it reports `{ sent, failed, skipped }` and counts owners without an email as `skipped`.
16. **PDF rendering failures never block an email.** If `htmlToPdf` throws (no browser on the host), the reminder or invoice email is sent without the attachment, and the failure is logged with `app.log.warn`. The document is always retrievable from `GET /reminders/:id/pdf` afterwards.
17. **`GET /api/reminders/:id/html` exists next to `/pdf`**, exactly as invoices already have both, so the document's content is testable without a browser.
18. **Cron runs from the host crontab, not a compose service.** The api container only `expose`s 3001, so the host reaches it through Caddy at `https://$DOMAIN/api/jobs/reminders`. One crontab line beats a fourth container.

```ts
import type { ReminderRules } from '../country/types.js';
import { comparePeriods, nextPeriod } from '../period.js';

/** One unpaid invoice of a single owner in a single building. `dueAt` is an ISO date or date-time. */
export interface UnpaidInvoice {
  id: string;
  period: string;
  dueAt: string;
  outstandingMinor: number;
}

/** A reminder already created for this owner in this building. `sentAt` is `sentAt ?? createdAt` on the API side. */
export interface PriorReminder {
  sentAt: string;
  invoiceIds: string[];
}

export interface OwnerReminderInput {
  invoices: UnpaidInvoice[];
  priorReminders: PriorReminder[];
}

export type ReminderReason = 'consecutive' | 'total';

export interface ReminderEvaluation {
  due: boolean;
  reason: ReminderReason | null;
  invoiceIds: string[];
}

const SUPPRESSION_MS = 30 * 24 * 60 * 60 * 1000;
/** A fresh object every time: callers own the result and may sort or push into `invoiceIds`. */
const notDue = (): ReminderEvaluation => ({ due: false, reason: null, invoiceIds: [] });

/** Longest run of consecutive months in an ascending list of distinct periods. */
function longestRun(periods: string[]): number {
  let best = 1;
  let run = 1;
  for (let i = 1; i < periods.length; i += 1) {
    run = periods[i]! === nextPeriod(periods[i - 1]!) ? run + 1 : 1;
    if (run > best) best = run;
  }
  return best;
}

/**
 * Art. 28 of the Law on Housing (MK): a reminder is due when `rules.consecutiveUnpaid` consecutive
 * periods are unpaid and past due, or `rules.totalUnpaid` periods in total are, and no reminder
 * covering the same debt went out in the last 30 days. `rules.feeAllowed` is never read because
 * nothing here produces a fee: there is no code path in domar that books one.
 */
export function evaluateOwner(input: OwnerReminderInput, rules: ReminderRules, today: Date): ReminderEvaluation {
  const nowMs = today.getTime();
  const overdue = input.invoices.filter((i) => i.outstandingMinor > 0 && Date.parse(i.dueAt) < nowMs);
  if (overdue.length === 0) return notDue();

  const periods = [...new Set(overdue.map((i) => i.period))].sort((a, b) => comparePeriods(a, b));
  const reason: ReminderReason | null = longestRun(periods) >= rules.consecutiveUnpaid
    ? 'consecutive'
    : periods.length >= rules.totalUnpaid
      ? 'total'
      : null;
  if (reason === null) return notDue();

  // Sorted so the same debt always yields the same set, whatever order the query returned.
  const invoiceIds = overdue.map((i) => i.id).sort();
  const suppressed = input.priorReminders.some((r) =>
    nowMs - Date.parse(r.sentAt) < SUPPRESSION_MS && invoiceIds.every((id) => r.invoiceIds.includes(id)));
  return suppressed ? notDue() : { due: true, reason, invoiceIds };
}
```

```ts
import nodemailer, { type Transporter } from 'nodemailer';
import type { Config } from '../config.js';

export interface MailAttachment { filename: string; content: Buffer; contentType: string }
export interface MailMessage { to: string; subject: string; text: string; attachments?: MailAttachment[] }
export type SendResult = { id: string } | { error: string };

export interface Mailer {
  readonly configured: boolean;
  /** Messages captured by the in-memory JSON transport (`SMTP_URL=json`); always empty for real SMTP. */
  readonly outbox: MailMessage[];
  send(msg: MailMessage): Promise<SendResult>;
  close(): Promise<void>;
}

/**
 * Without SMTP_URL the mailer is an explicit no-op: `send` answers `{ error: 'smtp_not_configured' }`
 * so the caller can record the failure, and nothing ever throws for lack of email (spec §18.5).
 */
export function createMailer(config: Config): Mailer {
  const outbox: MailMessage[] = [];
  if (!config.smtpUrl) {
    return {
      configured: false,
      outbox,
      async send() { return { error: 'smtp_not_configured' }; },
      async close() { /* nothing to close */ },
    };
  }
  const capture = config.smtpUrl === 'json';
  const transport: Transporter = capture
    ? nodemailer.createTransport({ jsonTransport: true })
    : nodemailer.createTransport(config.smtpUrl);
  return {
    configured: true,
    outbox,
    async send(msg: MailMessage): Promise<SendResult> {
      try {
        const info = await transport.sendMail({
          from: config.emailFrom, to: msg.to, subject: msg.subject, text: msg.text,
          ...(msg.attachments ? { attachments: msg.attachments } : {}),
        });
        if (capture) outbox.push(msg);
        return { id: String(info.messageId) };
      } catch (err) {
        return { error: (err instanceof Error ? err.message : 'send_failed').slice(0, 500) };
      }
    },
    async close() { transport.close(); },
  };
}
```

```ts
const paidMinorSql = sql<string>`(select coalesce(sum(p.amount_minor), 0) from ${schema.payments} p where p.tenant_id = "invoices"."tenant_id" and p.invoice_id = "invoices"."id" and p.status = 'completed')`;

export interface OwnerOverdue { contactId: string; invoices: UnpaidInvoice[] }

/** Overdue published invoices of a building, grouped by owner. Invoices without a due date never count. */
export async function overdueByOwner(db: Db, ctx: TenantContext, buildingId: string, now: Date): Promise<OwnerOverdue[]> {
  const rows = await db.select({ id: INV.id, contactId: INV.contactId, period: BP.period, dueAt: INV.dueAt, totalMinor: INV.totalMinor, paidMinor: paidMinorSql })
    .from(INV).innerJoin(BP, eq(BP.id, INV.periodId))
    .where(and(eq(INV.tenantId, ctx.tenantId), eq(INV.buildingId, buildingId), inArray(INV.status, ['published', 'partially_paid']), lt(INV.dueAt, now)));
  const byOwner = new Map<string, UnpaidInvoice[]>();
  for (const r of rows) {
    const outstandingMinor = r.totalMinor - Number(r.paidMinor);
    if (outstandingMinor <= 0) continue;
    const list = byOwner.get(r.contactId) ?? [];
    list.push({ id: r.id, period: r.period, dueAt: r.dueAt!.toISOString(), outstandingMinor });
    byOwner.set(r.contactId, list);
  }
  return [...byOwner].map(([contactId, invoices]) => ({ contactId, invoices })).sort((x, y) => x.contactId.localeCompare(y.contactId));
}

/**
 * Reminders created for this building since `since`, keyed by contact. A reminder that was created
 * but never sent (a pending letter, a failed email) still counts as sent, or the job would create a
 * duplicate every night.
 */
export async function priorRemindersByOwner(db: Db, ctx: TenantContext, buildingId: string, since: Date): Promise<Map<string, PriorReminder[]>> {
  const rows = await db.select({ contactId: R.contactId, sentAt: R.sentAt, createdAt: R.createdAt, invoiceIds: R.invoiceIds })
    .from(R).where(and(eq(R.tenantId, ctx.tenantId), eq(R.buildingId, buildingId), gte(R.createdAt, since)));
  const out = new Map<string, PriorReminder[]>();
  for (const r of rows) {
    const list = out.get(r.contactId) ?? [];
    list.push({ sentAt: (r.sentAt ?? r.createdAt).toISOString(), invoiceIds: r.invoiceIds });
    out.set(r.contactId, list);
  }
  return out;
}

export async function decorate(db: Db, ctx: TenantContext, rows: ReminderRecord[]) {
  if (rows.length === 0) return [];
  const contactIds = [...new Set(rows.map((r) => r.contactId))];
  const invoiceIds = [...new Set(rows.flatMap((r) => r.invoiceIds))];
  const [contacts, invoices] = await Promise.all([
    db.select({ id: C.id, firstName: C.firstName, lastName: C.lastName, email: C.email }).from(C).where(and(eq(C.tenantId, ctx.tenantId), inArray(C.id, contactIds))),
    invoiceIds.length === 0 ? Promise.resolve([]) : db.select({ id: INV.id, number: INV.number }).from(INV).where(and(eq(INV.tenantId, ctx.tenantId), inArray(INV.id, invoiceIds))),
  ]);
  const byContact = new Map(contacts.map((c) => [c.id, c]));
  const numberOf = new Map(invoices.map((i) => [i.id, i.number]));
  return rows.map((r) => ({
    id: r.id, buildingId: r.buildingId, contactId: r.contactId, reason: r.reason, invoiceIds: r.invoiceIds,

}
```

```ts
export interface ReminderRuntime {

/** Evaluates one building now, inserts the due reminders, then sends the email ones after the commit. */
export async function runBuildingReminders(db: Db, ctx: TenantContext, buildingId: string, rt: ReminderRuntime, now: Date = new Date()) {
  const building = await getBuilding(db, ctx, buildingId);
  const tenant = (await db.query.tenants.findFirst({ where: eq(T.id, ctx.tenantId) }))!;
  const pack = getCountryPack(tenant.countryCode as CountryCode);

  const [overdue, priors] = await Promise.all([
    overdueByOwner(db, ctx, buildingId, now),
    priorRemindersByOwner(db, ctx, buildingId, new Date(now.getTime() - PRIOR_WINDOW_MS)),
  ]);

  const plans = overdue.flatMap((o) => {
    const ev = evaluateOwner({ invoices: o.invoices, priorReminders: priors.get(o.contactId) ?? [] }, pack.reminderRules, now);
    if (!ev.due || ev.reason === null) return [];
    const covered = o.invoices.filter((i) => ev.invoiceIds.includes(i.id));
    return [{ contactId: o.contactId, reason: ev.reason, invoiceIds: ev.invoiceIds, covered }];
  });
  if (plans.length === 0) return { rows: [] };

  const allInvoiceIds = [...new Set(plans.flatMap((p) => p.invoiceIds))];
  const [contacts, invoiceNumbers] = await Promise.all([
    db.select().from(C).where(and(eq(C.tenantId, ctx.tenantId), inArray(C.id, plans.map((p) => p.contactId)))),
    db.select({ id: INV.id, number: INV.number }).from(INV).where(and(eq(INV.tenantId, ctx.tenantId), inArray(INV.id, allInvoiceIds))),
  ]);
  const contactById = new Map(contacts.map((c) => [c.id, c]));
  const numberOf = new Map(invoiceNumbers.map((i) => [i.id, i.number]));

  const values = plans.map((p) => {
    const contact = contactById.get(p.contactId)!;
    const invoices: ReminderHtmlInvoice[] = p.covered
      .map((i) => ({ number: numberOf.get(i.id) ?? null, period: i.period, dueAt: i.dueAt, outstandingMinor: i.outstandingMinor }))
      .sort((x, y) => x.period.localeCompare(y.period));
    const totalOutstandingMinor = p.covered.reduce((s, i) => s + i.outstandingMinor, 0);
    const documentHtml = renderReminderHtml({
      tenant, building, contact, invoices, totalOutstandingMinor,
      labels: { reminderIntro: pack.labels.reminderIntro, reminderLegal: pack.labels.reminderLegal },
      formatMoney: pack.formatMoney, locale: 'mk', createdAt: now,
    });
    return {
      tenantId: ctx.tenantId, buildingId, contactId: p.contactId, reason: p.reason, invoiceIds: p.invoiceIds,
      totalOutstandingMinor, channel: (contact.email ? 'email' : 'letter') as 'email' | 'letter',
      status: 'pending' as const, documentHtml,
    };
  });

  const inserted = await db.transaction(async (tx) => {
    const rows = await tx.insert(R).values(values).returning();
    await writeAudit(tx, ctx, {
      action: 'reminder.create', entityType: 'building', entityId: buildingId,
      after: { created: rows.map((r) => ({ id: r.id, contactId: r.contactId, reason: r.reason, channel: r.channel, totalOutstandingMinor: r.totalOutstandingMinor, invoiceIds: r.invoiceIds })) },
    });
    return rows;
  });

  // After the commit: a failed send updates the row, it never rolls the reminder back (spec §18.8).
  for (const row of inserted) {
    if (row.channel !== 'email') continue;
    const contact = contactById.get(row.contactId)!;
    await sendReminderEmail(db, ctx, row, contact.email!, building.name, pack, rt);
  }
  return listByIds(db, ctx, inserted.map((r) => r.id));
}

type Pack = ReturnType<typeof getCountryPack>;

async function sendReminderEmail(db: Db, ctx: TenantContext, row: ReminderRecord, to: string, buildingName: string, pack: Pack, rt: ReminderRuntime) {
  const subject = `Опомена за неплатени пресметки — ${buildingName}`;
  const text = [
    buildingName,
    '',
    pack.labels.reminderIntro,
    '',
    `Вкупен долг: ${pack.formatMoney(row.totalOutstandingMinor)}`,
    '',
    pack.labels.reminderLegal,
  ].join('\n');
  let attachments: { filename: string; content: Buffer; contentType: string }[] | undefined;
  try {
    attachments = [{ filename: `opomena-${row.id}.pdf`, content: await htmlToPdf(row.documentHtml, rt.pdfBrowserChannel), contentType: 'application/pdf' }];
  } catch (err) {
    // The letter stays available at GET /reminders/:id/pdf; the debt list is in the plain-text body.
    rt.log.warn({ err, reminderId: row.id }, 'reminder pdf render failed; sending without attachment');
  }
  const res = await rt.mailer.send({ to, subject, text, ...(attachments ? { attachments } : {}) });
  const ok = 'id' in res;
  const error = ok ? null : res.error;
  await db.transaction(async (tx) => {
    await tx.update(R).set({ status: ok ? 'sent' : 'failed', sentAt: ok ? new Date() : null, error })
      .where(and(eq(R.tenantId, ctx.tenantId), eq(R.id, row.id)));
    await logEmail(tx, ctx, { to, subject, template: 'reminder', refType: 'reminder', refId: row.id, status: ok ? 'sent' : 'failed', error });
    await writeAudit(tx, ctx, { action: 'reminder.send', entityType: 'reminder', entityId: row.id, after: { status: ok ? 'sent' : 'failed', to, error } });
  });
}

/** Claim-first: only a pending letter can be marked printed. */
export async function markPrinted(db: Db, ctx: TenantContext, id: string) {
  return db.transaction(async (tx) => {
    const [claimed] = await tx.update(R).set({ status: 'printed', sentAt: new Date() })
      .where(and(eq(R.tenantId, ctx.tenantId), eq(R.id, id), eq(R.channel, 'letter'), eq(R.status, 'pending'))).returning();
    if (!claimed) {
      await getReminderRow(tx, ctx, id); // 404 across tenants, otherwise it is simply not pending
      throw conflict('not_pending', 'Only a pending letter reminder can be marked printed');
    }
    await writeAudit(tx, ctx, { action: 'reminder.printed', entityType: 'reminder', entityId: id, after: { status: 'printed' } });
    const [out] = await decorate(tx, ctx, [claimed]);
    return out!;
  });
}

/** The cron entry point: every building of every tenant, with a null user in the audit trail. */
export async function runAllTenants(db: Db, rt: ReminderRuntime, now: Date = new Date()) {
  const tenants = await db.select({ id: T.id }).from(T);
  let buildings = 0;
  let reminders = 0;
  for (const tenant of tenants) {
    const ctx: TenantContext = { tenantId: tenant.id, userId: null, role: 'owner' };
    const rows = await db.select({ id: B.id }).from(B).where(eq(B.tenantId, tenant.id));
    for (const b of rows) {
      buildings += 1;
      const res = await runBuildingReminders(db, ctx, b.id, rt, now);
      reminders += res.rows.length;
    }
  }
  return { tenants: tenants.length, buildings, reminders };
}
```

```ts
import type { TenantContext } from '../tenant-context.js';

const INV = schema.invoices; const T = schema.tenants;
const SENDABLE = ['published', 'partially_paid', 'paid'] as const;

/** Emails one invoice's PDF to its owner. 409 when the owner has no email or the invoice is a draft. */
export async function sendInvoiceEmail(db: Db, ctx: TenantContext, invoiceId: string, rt: ReminderRuntime) {
  const invoice = await getInvoice(db, ctx, invoiceId); // 404 across tenants
  if (!SENDABLE.includes(invoice.status as (typeof SENDABLE)[number])) throw conflict('invoice_not_sendable', 'Only a published invoice can be emailed');
  const to = invoice.contact.email;
  if (!to) throw conflict('no_email', 'This owner has no email address');

  const tenant = (await db.query.tenants.findFirst({ where: eq(T.id, ctx.tenantId) }))!;
  const pack = getCountryPack(tenant.countryCode as CountryCode);
  const html = renderInvoiceHtml({ invoice, tenant, formatMoney: pack.formatMoney, locale: 'mk' });
  const name = (invoice.number ?? `draft-${invoice.id}`).replace(/[^A-Za-z0-9_.-]/g, '_');
  const subject = `Фактура ${invoice.number ?? invoice.id} — ${invoice.building.name}`;
  const text = [
    `${invoice.building.name}`,
    '',
    `Во прилог е пресметката ${invoice.number ?? invoice.id} за периодот ${invoice.period}.`,
    `Вкупно за плаќање: ${pack.formatMoney(invoice.amountDueMinor)}`,
    `Рок за плаќање: ${invoice.dueAt ? new Date(invoice.dueAt).toLocaleDateString('mk-MK') : '—'}`,
  ].join('\n');

  let attachments: { filename: string; content: Buffer; contentType: string }[] | undefined;
  try {
    attachments = [{ filename: `${name}.pdf`, content: await htmlToPdf(html, rt.pdfBrowserChannel), contentType: 'application/pdf' }];
  } catch (err) {
    rt.log.warn({ err, invoiceId }, 'invoice pdf render failed; sending without attachment');
  }
  const res = await rt.mailer.send({ to, subject, text, ...(attachments ? { attachments } : {}) });
  const ok = 'id' in res;
  const error = ok ? null : res.error;
  await db.transaction(async (tx) => {
    await logEmail(tx, ctx, { to, subject, template: 'invoice', refType: 'invoice', refId: invoiceId, status: ok ? 'sent' : 'failed', error });
    await writeAudit(tx, ctx, { action: 'invoice.send', entityType: 'invoice', entityId: invoiceId, after: { status: ok ? 'sent' : 'failed', to, error } });
  });
  return { id: invoiceId, status: (ok ? 'sent' : 'failed') as 'sent' | 'failed', to, error };
}

/** Emails every sendable invoice of a period. Owners without an email are skipped, never an error. */
export async function sendPeriodEmails(db: Db, ctx: TenantContext, buildingId: string, periodId: string, rt: ReminderRuntime) {
  await getPeriodRow(db, ctx, buildingId, periodId); // 404 across tenants
  const rows = await db.select({ id: INV.id, contactId: INV.contactId }).from(INV)
    .where(and(eq(INV.tenantId, ctx.tenantId), eq(INV.periodId, periodId), inArray(INV.status, [...SENDABLE])));
  let sent = 0; let failed = 0; let skipped = 0;
  for (const row of rows) {
    try {
      const res = await sendInvoiceEmail(db, ctx, row.id, rt);
      if (res.status === 'sent') sent += 1; else failed += 1;
    } catch (err) {
      // `no_email` is the only expected refusal here and it means "this owner gets a paper copy".
      if (err instanceof Error && 'code' in err && (err as { code: unknown }).code === 'no_email') skipped += 1;
      else throw err;
    }
  }
  return { sent, failed, skipped };
}
```

and insert this section between "## Updating" and "## Why the image runs `tsx`":

```markdown
## Reminders

domar has no in-process scheduler. `POST /api/jobs/reminders` evaluates every building of every
tenant and is authenticated by the `x-job-token` header alone, so anything that can make an HTTPS
request can drive it. One host crontab line is enough — the api container only `expose`s 3001, so
the request goes through Caddy:

    5 3 * * * cd /srv/domar && . ./.env && curl -fsS -m 300 -X POST -H "x-job-token: $JOB_TOKEN" "https://$DOMAIN/api/jobs/reminders" >> /var/log/domar-reminders.log 2>&1

`. ./.env` reads `JOB_TOKEN` and `DOMAIN` out of the same file compose uses; every value in `.env`
that contains spaces must be quoted for that to work (`.env.example` already quotes `EMAIL_FROM`).
The job is idempotent: a reminder is never created twice for the same debt inside 30 days, so a
missed night or a double run costs nothing. The endpoint answers `401` without the header, `403`
with the wrong token and `503` when `JOB_TOKEN` is unset on the server.

Without `SMTP_URL` the mailer is a no-op: reminders are still created and their letters are still
rendered at `GET /api/reminders/:id/pdf`, but every email reminder is recorded as `failed` with
`smtp_not_configured`. The building's "Reminders" tab shows that state, and Settings shows whether
email is configured at all.

For local development, `docker compose up -d mailpit` gives SMTP on `localhost:1025` and a web
inbox on `http://localhost:8025`; point `SMTP_URL=smtp://localhost:1025` at it.
```

```ts
import { expect, test } from '@playwright/test';

const API = 'http://localhost:3001';
const slug = `e2e-rem-${Date.now().toString(36)}`;
const password = 'correct-horse-1';
const daysAgo = (n: number) => new Date(Date.now() - n * 86_400_000).toISOString();

test('two overdue periods produce an emailed reminder with a PDF letter', async ({ page }) => {
  await page.goto('/register');
  await page.getByTestId('orgName').fill('Е2Е Опомени');
  await page.getByTestId('slug').fill(slug);
  await page.getByTestId('firstName').fill('Ева');
  await page.getByTestId('lastName').fill('Тест');
  await page.getByTestId('email').fill(`eva@${slug}.mk`);
  await page.getByTestId('password').fill(password);
  await page.getByRole('button', { name: /Отвори сметка|Create account/ }).click();
  await expect(page).toHaveURL(/\/app$/);

  // Seed through the API with the session cookie the registration just set; page.request shares the
  // browser context's cookie jar. Due dates in the past are only reachable through publish's dueAt.
  const post = async (path: string, data: unknown = {}) => {
    const res = await page.request.post(`${API}${path}`, { data });
    expect(res.status(), `${path} → ${await res.text()}`).toBeLessThan(300);
    return res.json();
  };
  const taxRates = await (await page.request.get(`${API}/api/tax-rates`)).json();
  const vatId = taxRates.rows.find((r: { rateBp: number }) => r.rateBp === 1800).id;
  const owner = await post('/api/contacts', { firstName: 'Марко', lastName: 'Марков', email: `marko@${slug}.mk` });
  const building = await post('/api/buildings', { name: 'Партизанска 12', address: 'Партизанска 12', city: 'Скопје', postalCode: '1000' });
  await post(`/api/buildings/${building.id}/units`, { label: '1', kind: 'apartment', areaM2: 50, ownerContactId: owner.id });
  const service = await post('/api/services', { name: 'Чистење', pricing: 'fixed_per_unit', defaultPriceMinor: 30000, taxRateId: vatId, appliesTo: ['apartment'] });
  await post(`/api/buildings/${building.id}/services`, { serviceId: service.id, startsPeriod: '2026-01' });
  for (const [period, days] of [['2026-07', 75], ['2026-08', 45]] as const) {
    const p = await post(`/api/buildings/${building.id}/periods`, { period });
    await post(`/api/buildings/${building.id}/periods/${p.id}/generate`);
    await post(`/api/buildings/${building.id}/periods/${p.id}/publish`, { dueAt: daysAgo(days) });
  }

  // Run the evaluation from the UI.
  await page.goto(`/app/buildings/${building.id}?tab=reminders`);
  await page.getByTestId('reminders-run').click();
  await expect(page.getByTestId('reminders-created')).toHaveText('Изготвени опомени: 1');
  await expect(page.getByTestId('reminder-reason')).toHaveText('Две последователни неплатени');
  await expect(page.getByTestId('reminder-status')).toHaveText('Испратена');

  // The letter renders as a real PDF.
  const href = await page.getByTestId('reminder-pdf').getAttribute('href');
  expect(href).toContain('/api/reminders/');
  const pdf = await page.request.get(href!);
  expect(pdf.status()).toBe(200);
  expect(pdf.headers()['content-type']).toContain('application/pdf');
  expect((await pdf.body()).subarray(0, 4).toString()).toBe('%PDF');

  // Running again inside 30 days creates nothing.
  await page.getByTestId('reminders-run').click();
  await expect(page.getByTestId('reminders-created')).toHaveText('Нема нови опомени.');
  await expect(page.getByTestId('row')).toHaveCount(1);

  // And one invoice can be emailed from its own page.
  const invoices = await (await page.request.get(`${API}/api/invoices?buildingId=${building.id}&pageSize=50`)).json();
  await page.goto(`/app/invoices/${invoices.rows[0].id}`);
  await page.getByTestId('send-email').click();
  await expect(page.getByTestId('send-email-status')).toHaveText('Испратено');
});
```
