# Domar Assembly (Art. 37) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A manager opens a building, schedules the annual assembly, writes the agenda and the decisions that will be voted on, and presses **Send invitations**. Every owner of the building gets an invitation — by email with the invitation PDF attached, on paper when there is no address — at least 15 days before the date, or, if the law's 15 days are not there, only after typing a reason that is audited, stamped onto the `assembly_invited` legal event and shown on the compliance screen as `late_invitation`. Owners open the portal, read the agenda and vote per decision while the window is open; they may change their mind until the manager closes it. On the day, the manager ticks the attendance sheet (proxies included), types the paper votes, and presses **Hold**: domar tallies every decision against the quorum basis the assembly was created with, renders the minutes as a PDF, files it as a `minutes` document the owners can download from the portal, writes `assembly_held` with the whole tally as evidence, and the Art. 37 card on the compliance screen turns green. Art. 37 stops being a duty the manager remembers and becomes a duty the system evidences.

**Architecture:** `@domar/db` gains one migration (`0010`) and one schema file, `packages/db/src/schema/assembly.ts`: `assemblies` (with a jsonb `agenda`), `assembly_invitations`, `assembly_attendance`, `assembly_decisions`, `assembly_votes` and seven enums. `@domar/domain` gains `src/assembly/tally.ts` — a pure `tallyDecision(basis, owners, attendance, votes)` that turns weights, presence and cast votes into one decision's result — plus two label fields on the country pack (`assemblyInvitationIntro`, `assemblyLegal`). `apps/api` gains `resources/assemblies/{schema,repo,service,hold,routes}.ts`, the two document templates `pdf/assembly-invitation-html.ts` and `pdf/assembly-minutes-html.ts`, one helper on `resources/documents/repo.ts` (`createDocumentFromBuffer`, for a document this process produced rather than received), the portal's first write route in `portal/{assembly-repo,assembly-routes}.ts`, and a switch inside `resources/compliance/snapshot.ts` from `legal_events` to the `assemblies` table for the three assembly fields of the snapshot. `apps/web` gains an `assemblies` tab on the building page (`components/building/AssembliesTab.vue` plus `components/assembly/AssemblyPanel.vue`) and two portal pages (`pages/portal/PortalAssembliesPage.vue`, `pages/portal/PortalAssemblyPage.vue`). `e2e/tests/assembly.spec.ts` walks the whole thing with two browser contexts.

**Tech Stack:** unchanged (Node 24, pnpm 10, TS strict, Fastify 5 + zod, Drizzle 0.36 + Postgres 16, Vue 3 + Vite + vue-i18n + Tailwind 4, Vitest, Playwright 1.63.0). **No new package.** The PDF renderer (`pdf/html-to-pdf.ts`), the mailer (`email/mailer.ts`), the document store (`documents/store.ts`) and the legal-event writer (`legal-events.ts`) already exist and are reused unchanged.

**Spec:** `docs/superpowers/specs/2026-09-24-domar-phase2-design.md` §6 (assembly), §3 (legal events, the `assembly` duty and its `late_invitation` flag), §4 (documents), §9 (notifications land in sub-plan 5 — here an owner is reached by email and by the portal page, nothing else), §10 (roles), §11 (invariants). Phase 1: `docs/superpowers/specs/2026-09-21-domar-phase1-design.md` §16 (global constraints), §10 (auth and tenancy), §11 (API shape), §12 (web), §19 (the portal). Previous plans: `2026-09-24-08-compliance.md` (this plan's style, the legal-event writer, the compliance evaluator, the document store), `2026-09-24-05-reminders.md` (the two-transaction send pattern, `markPrinted`, the letter/email channel split), `2026-09-24-06-owner-portal.md` (`resolveLink`, `assertOwnsUnitIn`, the portal shell).

## Design addendum (decisions not spelled out in the spec)

1. **The agenda is jsonb on the assembly, not a table.** `assemblies.agenda` is `jsonb not null default '[]'` typed `AgendaItem[] = { id: string; title: string; text: string }[]`. Spec §6 already writes "`agenda` (jsonb items)". An agenda item is never referenced by any other row — a vote hangs off a *decision*, not off an agenda point — so a table would buy ordering and joins nobody needs and cost a migration, a repo and a route. The `id` is a server-generated uuid so the web can `v-for :key` on it and reorder without a remount; a client-supplied `id` is accepted and kept (the edit form round-trips it), anything missing gets `randomUUID()`.
2. **Quorum weights are integers in basis points of the building, and the basis is per assembly.** `assemblies.quorum_basis` is `share` or `count`, chosen at creation and frozen from the moment invitations go out (it is part of `PATCH` only while `draft`).
   - `share`: an owner's weight is `Σ round(unit.ownership_share × 10000)` over the units they own in that building. Basis points, not the raw `numeric(9,6)`, because the tally must be exact integer arithmetic — a float sum of 0.6 + 0.4 is not 1 — and because the minutes print whole numbers.
   - `count`: every owner weighs exactly `1`, however many units they hold.
   - `basisTotal` is the **sum of the actual weights**, not a notional 10000: a building whose shares sum to 0.98 must have its quorum measured against what it really has, not against a number the data does not support.
3. **A `share` quorum refuses to run on incomplete data.** `assemblyOwners(db, ctx, buildingId, 'share')` throws `400 missing_ownership_shares` (with the offending unit labels in `details.units`) when any unit that has an owner has a null `ownership_share`. The alternative — treating a missing share as weight 0 — silently disenfranchises an owner and silently lowers the quorum bar, which is exactly the class of bug that makes a decision contestable. The same function throws `400 no_owners` for a building where no unit has an owner. Both fire at invite time and again at hold time, because the units can change in between.
4. **Quorum is reached when the present weight is *strictly more* than half the basis.** `present × 2 > basisTotal`. Exactly 50 % is not a quorum: "повеќе од половина" is more than half, and a test locks the boundary (`5000` present of `10000` → `no_quorum`).
5. **A decision passes when `for > against` among the cast votes *and* the quorum was reached.** `abstain` is tallied and printed but never moves the comparison — an abstention is a recorded refusal to decide, not a vote against. `result` is one of `passed`, `rejected`, `no_quorum` (plus `pending` in the database, the value a decision carries before the assembly is held). A tie (`for === against`) is `rejected`: a proposal that did not win a majority did not pass.
6. **`tallyDecision` is pure and owns the whole rule.** `packages/domain/src/assembly/tally.ts` exports `tallyDecision(basis, owners, attendance, votes)`. `owners[].weight` is always the *share* weight in basis points; the function itself applies the basis (`count` → 1 per owner), so the caller stores one weight per owner and the domain decides what it means. Votes are counted **only from owners marked present**, one per contact (the first entry wins; the database's unique index makes a second one impossible anyway), and a vote from a contact who is not an owner of this building is ignored. That gives the invariant `for + against + abstain ≤ present`, which a test asserts.
7. **Voting is per assembly, presence is merged at hold.** The window opens when `status` becomes `invited` and closes when the assembly becomes `held` or `cancelled`; a vote outside it is `409 voting_closed`. At hold, the attendance the manager submitted is **merged with the voters**: every owner who cast at least one vote is marked present, because casting a vote is participating. The manager's sheet therefore only has to carry the people who came in person or by proxy and did not vote electronically. One consequence, stated so it is not a surprise: a paper vote the manager types for an owner automatically makes that owner present.
8. **The 15-day rule is measured against `scheduled_at` at invite time; the compliance flag is measured against `held_at`.** `POST /assemblies/:id/invite` refuses with `409 invitation_too_late` when `floor((scheduled_at − now) / 1 day) < pack.complianceRules.assemblyInvitationMinDays` (15) unless the body carries `override: { reason }`; the override is audited, stored on the row (`late_invitation`, `late_reason`) and stamped into the `assembly_invited` evidence as `late: true, lateReason`. The compliance evaluator's `late_invitation` flag is computed by `packages/domain/src/compliance/evaluate.ts` from `lastAssemblyInvitedAt` versus `lastAssemblyHeldAt` and is **not changed by this plan**; the two agree whenever the assembly was held on the day it was scheduled for, which is the normal case and the one `holdAssembly`'s default `heldAt` produces.
9. **The compliance snapshot's three assembly fields move from `legal_events` to the `assemblies` table**, and only those three:
   - `assemblyCount` = number of assemblies of the building whose status is `invited` or `held` (so *calling* one already lifts the duty out of `n/a` into `due`, which is the honest reading: domar now knows the owners have been summoned and that the meeting has not happened yet). A `draft` does not count — it is the manager's notepad, nobody has been summoned, and a building whose only assembly is a draft is still one domar knows nothing about — and neither does a `cancelled` one, which summoned nobody.
   - `lastAssemblyHeldAt` = `held_at` of the newest `held` assembly.
   - `lastAssemblyInvitedAt` = the `invited_at` **of that same newest held assembly**, or, when nothing was ever held, the newest `invited_at` of any `invited` or `held` assembly. Pairing the two timestamps on one row is what makes the `late_invitation` flag exact; two independent maxima over the event log would flag a punctual assembly whenever a *later* one had been invited late.
   The events stay exactly where they are and remain the evidence trail — `assembly_invited` and `assembly_held` are still written, still append-only, still listed on the compliance screen. Spec §11's "the compliance screen never reads anything but events plus dates already in the system" is satisfied: `assemblies.held_at` and `assemblies.invited_at` are dates already in the system, of the same kind as `billing_periods.published_at`, which the snapshot has read since sub-plan 1.
10. **One invitation document per assembly, not one per owner.** The invitation is a notice (building, date, place, agenda, the proposed decisions, the Art. 37 sentence), not a personalised demand like the Art. 28 letter, so it is rendered once, stored on `assemblies.invitation_html`, and the same PDF is attached to every email. This makes the send loop render Chrome once instead of once per owner and makes `GET /assemblies/:id/invitation/pdf` a pure re-render of stored HTML.
11. **Invitations follow the reminder's two-transaction send pattern exactly.** Transaction one claims `draft → invited`, freezes one `assembly_invitations` row per owner contact (`email` when the contact has an address **and** `app.mailer.configured`, else `letter` with status `pending`, exactly as `runBuildingReminders` decides), stores the rendered HTML, writes `assembly_invited` and the audit row. After the commit, the PDF is rendered once and each email invitation is sent; each send's outcome is written in its own small transaction together with its `email_log` row. A failed send never rolls the invitation back — the assembly is invited, one owner's email bounced, and the manager marks that one printed instead.
12. **`assembly_invited` is written once, at invite time, and carries the delivery counts, not the deliveries.** Evidence: `{ assemblyId, scheduledAt, invitedAt, contacts: n, channels: { email, letter }, late: boolean, lateReason?: string }`. Individual sends are evidenced by `email_log` rows (joined to the invitation by `email_log_id`) and by the invitation rows' own `status`. Marking a letter printed writes an audit row and flips the invitation's status; it does **not** write a second legal event, because the duty ("the owners were invited, 15 days ahead") was discharged when the invitations were created, not when a printer finished.
13. **`hold` is one transaction, including the minutes PDF, and the whole thing rolls back if the renderer is unavailable.** The minutes are the evidence of Art. 37; an assembly that is `held` in the database with no minutes document is a record that lies. So `holdAssembly` claims the row, tallies, renders the HTML, renders the PDF, files the document, sets `minutes_document_id`, writes `assembly_held` and the audit row — all inside `db.transaction`. If `htmlToPdf` throws, the caller gets `503 pdf_unavailable` and the assembly is still `invited`, retryable. The only residue a mid-flight failure can leave is a file on disk with no row pointing at it (the store's `put` happens before the row insert); that is invisible, harmless, and the same residue the upload path can already leave.
14. **`createDocumentFromBuffer` is the seam for server-generated documents.** `resources/documents/repo.ts` already has `createDocument`, which consumes a `Readable` from a multipart part. The minutes (and, in sub-plan 3, the annual and handover reports) are produced by this process, so a four-line wrapper wraps the buffer in `Readable.from` and reports `isTruncated: () => false`. Everything else — the mime allowlist, the storage key, the sha256, the audit row — is the existing path, unchanged, so a generated document is indistinguishable from an uploaded one and the portal's `kind in ('minutes','report')` filter already lets the owners see it.
15. **`heldAt` defaults to `scheduled_at`.** The body may override it (an assembly postponed by an hour, minutes typed the next morning), but the default is the date the invitation announced, which is what actually happened in the overwhelming majority of cases and what keeps the 15-day evidence consistent. The only validation is `heldAt >= invited_at`: an assembly cannot have been held before it was called.
16. **`held` is terminal, `cancelled` is reachable from `draft` and `invited`.** Every transition is claim-first — a conditional `UPDATE … WHERE status IN (…) RETURNING`, exactly like `claimPeriod` — so two clicks cannot hold an assembly twice, and a loser gets `409` (or `404` if the row is another tenant's). Nothing deletes a held or cancelled assembly; `DELETE /assemblies/:id` works on a `draft` only.
17. **The portal gets its first write route, and it is fenced like every portal read.** `POST /api/portal/assemblies/:id/decisions/:decisionId/vote` resolves the link (`resolveLink`), asserts the contact owns a unit in the assembly's building (`assertOwnsUnitIn`), asserts the assembly is `invited`, and upserts on `(decision_id, contact_id)` so a change of mind replaces the vote instead of adding one. It writes an audit row under `portalTenantContext` (user id null, role `readonly`), and it carries a route-level rate limit (`30/minute`) because it is an unauthenticated-by-cookie-only write surface. Results (`for/against/abstain/result`) are `null` on the wire until the assembly is `held`: an open ballot whose running totals are visible is a ballot that can be gamed.
18. **What the portal sees.** `GET /portal/assemblies?contactId` lists the `invited` and `held` assemblies of every building the contact owns a unit in, newest date first; a `draft` is invisible (it is not a called assembly) and a `cancelled` one is invisible (it is not happening). The detail adds the agenda, the decisions, the caller's own vote per decision, the minutes document id once held, and a link to the invitation PDF. The minutes themselves are downloaded through the **existing** `GET /api/portal/documents/:id/download?contactId`, which already checks link, building and `kind in ('minutes','report')` — no new download route, no new check to get wrong.
19. **Enums are new types, not reused ones.** `assembly_channel` and `assembly_invitation_status` have the same labels as `reminder_channel` and `reminder_status`, and are still separate Postgres types: an assembly invitation is not a reminder, and the day one of them grows a label (`sms`, `cancelled`) the other must not grow it too.
20. **Task sizes.** Seven tasks: db, domain, the assembly API up to and including invitations, the voting/hold/portal/compliance half, the manager screen, the portal screens, and the end-to-end walk-through. Tasks 3 and 4 are the two big ones (~600 lines each including their tests) and are split at the natural seam: task 3 ends when the owners have been invited, task 4 starts when the first vote is cast.

export type QuorumBasis = 'share' | 'count';
export type VoteChoice = 'for' | 'against' | 'abstain';
export type DecisionResult = 'passed' | 'rejected' | 'no_quorum';

/** One owner of the building and the weight their ownership share is worth, in basis points. */
export interface AssemblyOwner {
  contactId: string;
  /** `Σ round(ownership_share × 10000)` over the owner's units. Always the *share* weight, even
   *  when the assembly runs a `count` quorum — `ownerWeight` decides what the basis makes of it. */
  weight: number;
}

export interface AssemblyAttendee {
  contactId: string;
  /** In person or by proxy; a proxy holder's name is bookkeeping, not arithmetic. */
  present: boolean;
}

export interface AssemblyVote {
  contactId: string;
  choice: VoteChoice;
}

export interface DecisionTally {
  for: number;
  against: number;
  abstain: number;
  /** Weight of the owners who were present; what the quorum is measured with. */
  present: number;
  /** Weight of every owner of the building. */
  basisTotal: number;
  quorumReached: boolean;
  result: DecisionResult;
}

/** An ownership share (0–1) as whole basis points, so every later sum is exact integer arithmetic. */
export function shareWeightBp(share: number): number {
  return Math.round(share * 10000);
}

/** What one owner weighs under a given basis: their share, or one owner-one-vote (plan addendum 2). */
export function ownerWeight(basis: QuorumBasis, owner: AssemblyOwner): number {
  return basis === 'count' ? 1 : owner.weight;
}

/**
 * Art. 37, one decision. Pure: the same owners, attendance and votes always give the same tally.
 *
 * - The quorum is reached when the present weight is **strictly more** than half the basis, so an
 *   assembly attended by exactly half the building decides nothing (plan addendum 4).
 * - A decision passes when `for > against` **and** the quorum was reached; a tie is a rejection,
 *   because a proposal that did not win a majority did not pass.
 * - Abstentions are tallied and never compared: they are a recorded refusal to decide.
 * - Only owners marked present are counted, at most one vote each, and a vote from somebody who
 *   owns nothing in this building is ignored — so `for + against + abstain ≤ present` always holds.
 */
export function tallyDecision(basis: QuorumBasis, owners: AssemblyOwner[], attendance: AssemblyAttendee[], votes: AssemblyVote[]): DecisionTally {
  const weightOf = new Map(owners.map((o) => [o.contactId, ownerWeight(basis, o)]));
  let basisTotal = 0;
  for (const w of weightOf.values()) basisTotal += w;

  const presentIds = new Set(attendance.filter((a) => a.present && weightOf.has(a.contactId)).map((a) => a.contactId));
  let present = 0;
  for (const id of presentIds) present += weightOf.get(id)!;

  const counted = new Set<string>();
  const cast = { for: 0, against: 0, abstain: 0 };
  for (const v of votes) {
    if (!presentIds.has(v.contactId) || counted.has(v.contactId)) continue;
    counted.add(v.contactId);
    cast[v.choice] += weightOf.get(v.contactId)!;
  }

  const quorumReached = present * 2 > basisTotal;
  const result: DecisionResult = !quorumReached ? 'no_quorum' : cast.for > cast.against ? 'passed' : 'rejected';
  return { ...cast, present, basisTotal, quorumReached, result };
}

export type AssemblyOwnerKey = 'A' | 'B' | 'C';
export interface AssemblyBuilding { buildingId: string; owners: Record<AssemblyOwnerKey, string> }

/**
 * A building for Art. 37: three owners with explicit ownership shares — 0.5 / 0.3 / 0.2, i.e.
 * 5000 / 3000 / 2000 basis points out of 10000 — so a quorum can be tested exactly on 50 % (A alone)
 * and clearly above it (A + B). `emails` decides who gets an email invitation and who gets a letter.
 */
export async function setupAssemblyBuilding(app: FastifyInstance, cookie: string, emails: Partial<Record<AssemblyOwnerKey, string>> = {}): Promise<AssemblyBuilding> {
  const h = { cookie };
  const post = (url: string, payload: Record<string, unknown>) => app.inject({ method: 'POST', url, headers: h, payload });
  const people: [AssemblyOwnerKey, string, number, number][] = [['A', 'Анастасова', 0.5, 50], ['B', 'Богданов', 0.3, 30], ['C', 'Цветков', 0.2, 20]];
  const buildingId = (await post('/api/buildings', { name: 'Востаничка 7', address: 'Востаничка 7', city: 'Скопје', postalCode: '1000' })).json().id;
  const owners = {} as Record<AssemblyOwnerKey, string>;
  for (const [k, lastName, share, area] of people) {
    owners[k] = (await post('/api/contacts', { firstName: 'Тест', lastName, ...(emails[k] ? { email: emails[k] } : {}) })).json().id;
    await post(`/api/buildings/${buildingId}/units`, { label: k, kind: 'apartment', areaM2: area, ownershipShare: share, ownerContactId: owners[k] });
  }
  return { buildingId, owners };
}

/**
 * The owners of the building and what each of them weighs, in basis points of the whole building.
 * A `share` quorum refuses to run on a building whose owned units have no share (plan addendum 3):
 * treating a missing share as zero would disenfranchise that owner *and* lower the quorum bar.
 */
export async function assemblyOwners(db: Db, ctx: TenantContext, buildingId: string, basis: QuorumBasisValue): Promise<AssemblyOwner[]> {
  const rows = await db.select({ ownerContactId: U.ownerContactId, ownershipShare: U.ownershipShare, label: U.label })
    .from(U).where(and(eq(U.tenantId, ctx.tenantId), eq(U.buildingId, buildingId)));
  const owned = rows.filter((r) => r.ownerContactId !== null);
  if (owned.length === 0) throw badRequest('no_owners', 'No unit in this building has an owner');
  if (basis === 'share') {
    const missing = owned.filter((r) => r.ownershipShare === null).map((r) => r.label).sort();
    if (missing.length > 0) {
      throw badRequest('missing_ownership_shares', `A 'share' quorum needs ownershipShare on every owned unit; these have none: ${missing.join(', ')}`, { units: missing });
    }
  }
  const byContact = new Map<string, number>();
  for (const r of owned) {
    const weight = r.ownershipShare === null ? 0 : shareWeightBp(Number(r.ownershipShare));
    byContact.set(r.ownerContactId!, (byContact.get(r.ownerContactId!) ?? 0) + weight);
  }
  return [...byContact].map(([contactId, weight]) => ({ contactId, weight })).sort((x, y) => x.contactId.localeCompare(y.contactId));
}

const DAY_MS = 86_400_000;

export interface AssemblyRuntime {

const wholeDaysUntil = (from: Date, to: Date) => Math.floor((to.getTime() - from.getTime()) / DAY_MS);

interface InvitationTextInput {

/** The plain-text twin of the invitation document, for clients that never open the attachment. */
function invitationText(x: InvitationTextInput): string {
  return [
    x.buildingName,
    '',
    x.labels.assemblyInvitationIntro,
    '',
    `Датум и час: ${formatAssemblyDateTime(x.scheduledAt, x.timeZone)}`,
    `Место: ${x.location || '—'}`,

/**
 * Art. 37. One transaction freezes who is invited, how, and that it happened; the sends follow after
 * the commit (plan addendum 11), so a dead SMTP server costs one owner an email and never un-invites
 * the building.
 */
export async function inviteAssembly(db: Db, ctx: TenantContext, id: string, input: { override?: { reason: string } | undefined }, rt: AssemblyRuntime) {
  const prepared = await db.transaction(async (tx) => {
    const claimed = await claimAssembly(tx, ctx, id, ['draft']);
    const building = await getBuilding(tx, ctx, claimed.buildingId);
    const { tenant, pack } = await tenantPack(tx, ctx);
    const now = new Date();
    const days = wholeDaysUntil(now, claimed.scheduledAt);
    if (days < 0) throw badRequest('assembly_in_the_past', 'This assembly is scheduled in the past');
    const minDays = pack.complianceRules.assemblyInvitationMinDays;
    const late = days < minDays;
    if (late && !input.override) {
      throw conflict('invitation_too_late', `Art. 37 asks for ${minDays} days; this assembly is ${days} days away`, { days, minDays });
    }
    const owners = await assemblyOwners(tx, ctx, claimed.buildingId, claimed.quorumBasis);
    const contacts = await tx.select().from(C)
      .where(and(eq(C.tenantId, ctx.tenantId), inArray(C.id, owners.map((o) => o.contactId))))
      .orderBy(asc(C.lastName), asc(C.firstName));
    const decisions = await listDecisionRows(tx, ctx, id);
    const labels = { assemblyInvitationIntro: pack.labels.assemblyInvitationIntro, assemblyLegal: pack.labels.assemblyLegal };
    const invitationHtml = renderAssemblyInvitationHtml({
      tenant, building, scheduledAt: claimed.scheduledAt, location: claimed.location,
      agenda: claimed.agenda, decisions: decisions.map((d) => ({ title: d.title, text: d.text })),
      labels, timeZone: tenant.timezone, locale: 'mk', createdAt: now,
    });
    // Without a configured mailer every invitation is a printable letter from the start, exactly as
    // `runBuildingReminders` decides it: a failed email row would be evidence of nothing.
    const invitations = await tx.insert(AI).values(contacts.map((c) => ({
      tenantId: ctx.tenantId, assemblyId: id, contactId: c.id,
      channel: (c.email && rt.mailer.configured ? 'email' : 'letter') as 'email' | 'letter',
      status: 'pending' as const,
    }))).returning();
    const channels = {
      email: invitations.filter((r) => r.channel === 'email').length,
      letter: invitations.filter((r) => r.channel === 'letter').length,
    };
    await tx.update(A).set({
      status: 'invited', invitedAt: now, lateInvitation: late,
      lateReason: input.override?.reason ?? null, invitationHtml, updatedAt: now,
    }).where(and(eq(A.tenantId, ctx.tenantId), eq(A.id, id)));
    await recordLegalEvent(tx, ctx, {
      buildingId: claimed.buildingId, kind: 'assembly_invited', refType: 'assembly', refId: id,
      occurredAt: now, dueAt: claimed.scheduledAt,
      evidence: {
        assemblyId: id, scheduledAt: claimed.scheduledAt.toISOString(), invitedAt: now.toISOString(),
        contacts: invitations.length, channels, late,
        ...(late ? { lateReason: input.override!.reason } : {}),
      },
    });
    await writeAudit(tx, ctx, {
      action: 'assembly.invite', entityType: 'assembly', entityId: id,
      before: publicAssembly(claimed),
      after: { contacts: invitations.length, channels, late, lateReason: input.override?.reason ?? null, daysAhead: days },
    });
    return {
      invitations, contacts, buildingName: building.name, timeZone: tenant.timezone, invitationHtml, labels,
      scheduledAt: claimed.scheduledAt, location: claimed.location, agenda: claimed.agenda, decisions,
    };
  });

  const emailed = prepared.invitations.filter((r) => r.channel === 'email');
  if (emailed.length > 0) {
    // One render for the whole building (plan addendum 10), and a missing attachment never stops
    // the notice: the body carries the date, the place and the agenda in full.
    let attachments: { filename: string; content: Buffer; contentType: string }[] | undefined;
    try {
      attachments = [{ filename: `pokana-${id}.pdf`, content: await htmlToPdf(prepared.invitationHtml, rt.pdfBrowserChannel), contentType: 'application/pdf' }];
    } catch (err) {
      rt.log.warn({ err, assemblyId: id }, 'assembly invitation pdf render failed; sending without attachment');
    }
    const subject = `Покана за собир — ${prepared.buildingName}`;
    const text = invitationText({
      buildingName: prepared.buildingName, scheduledAt: prepared.scheduledAt, location: prepared.location,
      agenda: prepared.agenda, decisions: prepared.decisions, labels: prepared.labels, timeZone: prepared.timeZone,
    });
    const emailOf = new Map(prepared.contacts.map((c) => [c.id, c.email]));
    for (const invitation of emailed) {
      const to = emailOf.get(invitation.contactId);
      if (!to) continue;
      try {
        const res = await rt.mailer.send({ to, subject, text, ...(attachments ? { attachments } : {}) });
        await recordInvitationSend(db, ctx, invitation.id, to, subject, res);
      } catch (err) {
        // A throw here (a dead transport, a failed log write) must not cost the remaining owners.
        rt.log.warn({ err, assemblyId: id, invitationId: invitation.id }, 'assembly invitation send threw; marked failed');
        await markInvitationFailed(db, ctx, invitation.id, err);
      }
    }
  }
  return getAssembly(db, ctx, id);
}

async function recordInvitationSend(db: Db, ctx: TenantContext, invitationId: string, to: string, subject: string, res: SendResult) {
  const ok = 'id' in res;
  const error = ok ? null : res.error;
  await db.transaction(async (tx) => {
    const logRow = await logEmail(tx, ctx, { to, subject, template: 'assembly_invitation', refType: 'assembly_invitation', refId: invitationId, status: ok ? 'sent' : 'failed', error });
    await tx.update(AI).set({ status: ok ? 'sent' : 'failed', sentAt: ok ? new Date() : null, error, emailLogId: logRow.id })
      .where(and(eq(AI.tenantId, ctx.tenantId), eq(AI.id, invitationId)));
    await writeAudit(tx, ctx, { action: 'assembly_invitation.send', entityType: 'assembly_invitation', entityId: invitationId, after: { status: ok ? 'sent' : 'failed', to, error } });
  });
}

/** Last-resort bookkeeping when a send throws outright, so an invitation is never left pending. */
async function markInvitationFailed(db: Db, ctx: TenantContext, invitationId: string, err: unknown) {
  const error = (err instanceof Error ? err.message : 'send_failed').slice(0, 500);
  await db.transaction(async (tx) => {
    await tx.update(AI).set({ status: 'failed', sentAt: null, error }).where(and(eq(AI.tenantId, ctx.tenantId), eq(AI.id, invitationId)));
    await writeAudit(tx, ctx, { action: 'assembly_invitation.send', entityType: 'assembly_invitation', entityId: invitationId, after: { status: 'failed', error } });
  });
}

/**
 * Claim-first, like `markPrinted` on a reminder: a letter that was never delivered can be marked
 * printed, and so can a failed email — paper is the fallback when the message never left the server.
 * No legal event: `assembly_invited` already evidences the duty (plan addendum 12).
 */
export async function markInvitationPrinted(db: Db, ctx: TenantContext, invitationId: string) {
  return db.transaction(async (tx) => {
    const [claimed] = await tx.update(AI).set({ status: 'printed', sentAt: new Date() })
      .where(and(eq(AI.tenantId, ctx.tenantId), eq(AI.id, invitationId), inArray(AI.status, ['pending', 'failed']))).returning();
    if (!claimed) {
      const [row] = await tx.select({ id: AI.id }).from(AI).where(and(eq(AI.tenantId, ctx.tenantId), eq(AI.id, invitationId))).limit(1);
      if (!row) throw notFound('Invitation'); // 404 across tenants
      throw conflict('not_pending', 'Only a pending or failed invitation can be marked printed');
    }
    await writeAudit(tx, ctx, { action: 'assembly_invitation.printed', entityType: 'assembly_invitation', entityId: invitationId, after: { status: 'printed' } });
    return getAssembly(tx, ctx, claimed.assemblyId);
  });
}

export async function cancelAssembly(db: Db, ctx: TenantContext, id: string, reason: string) {
  return db.transaction(async (tx) => {
    const before = await claimAssembly(tx, ctx, id, ['draft', 'invited']);
    const now = new Date();
    await tx.update(A).set({ status: 'cancelled', cancelledAt: now, cancelReason: reason, updatedAt: now })
      .where(and(eq(A.tenantId, ctx.tenantId), eq(A.id, id)));
    // No legal event: a cancelled assembly discharged nothing, and the audit row records who and why.
    await writeAudit(tx, ctx, { action: 'assembly.cancel', entityType: 'assembly', entityId: id, before: publicAssembly(before), after: { status: 'cancelled', cancelReason: reason } });
    return getAssembly(tx, ctx, id);
  });
}

export async function assemblyInvitationHtml(db: Db, ctx: TenantContext, id: string): Promise<string> {
  const row = await getAssemblyRow(db, ctx, id); // 404 across tenants
  if (!row.invitationHtml) throw conflict('not_invited', 'This assembly has not been called yet');
  return row.invitationHtml;
}

/**
 * One vote per contact per decision, changeable while the window is open: the unique index
 * `(decision_id, contact_id)` turns a change of mind into an UPDATE instead of a second row, and
 * two simultaneous clicks into one row rather than a unique violation.

export async function upsertVote(tx: Db, ctx: TenantContext, v: NewVote): Promise<void> {
  await tx.insert(AV).values({ tenantId: ctx.tenantId, ...v })
    .onConflictDoUpdate({ target: [AV.decisionId, AV.contactId], set: { choice: v.choice, via: v.via, castAt: new Date() } });

/** The manager typing what somebody wrote on paper. Same window, same one-vote rule as the portal. */
export async function castPaperVote(db: Db, ctx: TenantContext, id: string, decisionId: string, input: { contactId: string; choice: VoteChoice }) {
  return db.transaction(async (tx) => {
    const assembly = await getAssemblyRow(tx, ctx, id); // 404 across tenants
    if (assembly.status !== 'invited') throw conflict('voting_closed', 'Voting is open only while the assembly is called');
    const [decision] = await tx.select({ id: AD.id }).from(AD)
      .where(and(eq(AD.tenantId, ctx.tenantId), eq(AD.assemblyId, id), eq(AD.id, decisionId))).limit(1);
    if (!decision) throw notFound('Decision');
    const owners = await assemblyOwners(tx, ctx, assembly.buildingId, assembly.quorumBasis);
    if (!owners.some((o) => o.contactId === input.contactId)) {
      throw badRequest('invalid_reference', 'That contact owns no unit in this building');
    }
    await upsertVote(tx, ctx, { assemblyId: id, decisionId, contactId: input.contactId, choice: input.choice, via: 'paper' });
    await writeAudit(tx, ctx, {
      action: 'assembly_vote.cast', entityType: 'assembly_decision', entityId: decisionId,
      after: { contactId: input.contactId, choice: input.choice, via: 'paper' },
    });
    return getAssembly(tx, ctx, id);
  });
}

  return { rows, basisTotal: rows.reduce((s, r) => s + r.weightBp, 0), quorumBasis: assembly.quorumBasis };

import { and, eq, inArray } from 'drizzle-orm';
import { writeAudit } from '../../audit.js';

import type { TenantContext } from '../../tenant-context.js';
import { getBuilding } from '../buildings/repo.js';
import { createDocumentFromBuffer } from '../documents/repo.js';
import { assemblyOwners, claimAssembly, getAssembly, listDecisionRows, publicAssembly, tenantPack } from './repo.js';
import type { HoldBody } from './schema.js';
import type { AssemblyRuntime } from './service.js';

const A = schema.assemblies; const AD = schema.assemblyDecisions; const AT = schema.assemblyAttendance;
const AV = schema.assemblyVotes; const C = schema.contacts;

/**
 * Art. 37, the whole closing act in one transaction (plan addendum 13): the window shuts, every
 * decision is tallied against the basis the assembly was called with, the minutes are rendered and
 * filed as a `minutes` document, and `assembly_held` records the figures. If the PDF renderer is
 * unavailable the transaction rolls back and the assembly stays `invited` — an assembly that is
 * `held` with no minutes would be a record that lies.
 */
export async function holdAssembly(db: Db, ctx: TenantContext, id: string, input: HoldBody, rt: AssemblyRuntime) {
  return db.transaction(async (tx) => {
    const claimed = await claimAssembly(tx, ctx, id, ['invited']);
    const building = await getBuilding(tx, ctx, claimed.buildingId);
    const { tenant, pack } = await tenantPack(tx, ctx);
    // Plan addendum 15: the day the invitation announced, unless the manager says otherwise.
    const heldAt = input.heldAt ? new Date(input.heldAt) : claimed.scheduledAt;
    if (claimed.invitedAt && heldAt.getTime() < claimed.invitedAt.getTime()) {
      throw badRequest('held_before_invited', 'An assembly cannot have been held before it was called');
    }

    const owners = await assemblyOwners(tx, ctx, claimed.buildingId, claimed.quorumBasis);
    const ownerIds = new Set(owners.map((o) => o.contactId));
    const strangers = input.attendance.filter((r) => !ownerIds.has(r.contactId)).map((r) => r.contactId);
    if (strangers.length > 0) {
      throw badRequest('invalid_reference', 'The attendance sheet names somebody who owns no unit in this building', { contactIds: strangers });
    }

    const decisions = await listDecisionRows(tx, ctx, id);
    const votes = await tx.select().from(AV).where(and(eq(AV.tenantId, ctx.tenantId), eq(AV.assemblyId, id)));

    // Plan addendum 7: casting a vote is participating, so every voter is present whatever the sheet says.
    const voted = new Set(votes.filter((v) => ownerIds.has(v.contactId)).map((v) => v.contactId));
    const sheet = new Map(input.attendance.map((r) => [r.contactId, r]));
    const attendance = owners.map((o) => ({
      contactId: o.contactId,
      present: voted.has(o.contactId) || (sheet.get(o.contactId)?.present ?? false),
      proxyName: sheet.get(o.contactId)?.proxyName ?? null,
      weightBp: ownerWeight(claimed.quorumBasis, o),
    }));

    // An empty ballot gives the assembly-level quorum figures, identical for every decision.
    const quorum = tallyDecision(claimed.quorumBasis, owners, attendance, []);
    const tallies = decisions.map((decision) => ({
      decision,
      tally: tallyDecision(claimed.quorumBasis, owners, attendance,
        votes.filter((v) => v.decisionId === decision.id).map((v) => ({ contactId: v.contactId, choice: v.choice }))),
    }));

    await tx.insert(AT).values(attendance.map((r) => ({
      tenantId: ctx.tenantId, assemblyId: id, contactId: r.contactId, present: r.present, proxyName: r.proxyName, weightBp: r.weightBp,
    })));
    for (const { decision, tally } of tallies) {
      await tx.update(AD).set({
        forWeight: tally.for, againstWeight: tally.against, abstainWeight: tally.abstain,
        presentWeight: tally.present, basisTotal: tally.basisTotal, quorumReached: tally.quorumReached,
        result: tally.result, updatedAt: new Date(),
      }).where(and(eq(AD.tenantId, ctx.tenantId), eq(AD.id, decision.id)));
    }

    const contacts = await tx.select({ id: C.id, firstName: C.firstName, lastName: C.lastName }).from(C)
      .where(and(eq(C.tenantId, ctx.tenantId), inArray(C.id, owners.map((o) => o.contactId))));
    const nameOf = new Map(contacts.map((c) => [c.id, `${c.firstName} ${c.lastName}`.trim()]));
    const minutesHtml = renderAssemblyMinutesHtml({
      tenant, building, scheduledAt: claimed.scheduledAt, heldAt, location: claimed.location,
      agenda: claimed.agenda, quorumBasis: claimed.quorumBasis,
      quorum: { present: quorum.present, basisTotal: quorum.basisTotal, quorumReached: quorum.quorumReached },
      attendance: attendance.map((r) => ({ name: nameOf.get(r.contactId) ?? '', present: r.present, proxyName: r.proxyName, weightBp: r.weightBp })),
      decisions: tallies.map(({ decision, tally }) => ({
        title: decision.title, text: decision.text, for: tally.for, against: tally.against, abstain: tally.abstain, result: tally.result,
      })),
      labels: { assemblyLegal: pack.labels.assemblyLegal },
      timeZone: tenant.timezone, locale: 'mk',
    });

    let pdf: Buffer;
    try {
      pdf = await htmlToPdf(minutesHtml, rt.pdfBrowserChannel);
    } catch (err) {
      rt.log.warn({ err, assemblyId: id }, 'assembly minutes pdf render failed; the hold is rolled back');
      throw new AppError(503, 'pdf_unavailable', 'PDF rendering is not available on this server');
    }
    const document = await createDocumentFromBuffer(tx, ctx, rt.documents, {
      buildingId: claimed.buildingId, kind: 'minutes',
      title: `Записник од собир — ${formatAssemblyDate(heldAt, tenant.timezone)}`,
      fileName: `zapisnik-${id}.pdf`, mime: 'application/pdf', content: pdf,
    });

    await tx.update(A).set({ status: 'held', heldAt, minutesHtml, minutesDocumentId: document.id, updatedAt: new Date() })
      .where(and(eq(A.tenantId, ctx.tenantId), eq(A.id, id)));
    await recordLegalEvent(tx, ctx, {
      buildingId: claimed.buildingId, kind: 'assembly_held', refType: 'assembly', refId: id, occurredAt: heldAt,
      evidence: {
        assemblyId: id, heldAt: heldAt.toISOString(), quorumReached: quorum.quorumReached,
        present: quorum.present, basisTotal: quorum.basisTotal, quorumBasis: claimed.quorumBasis,
        decisions: tallies.map(({ decision, tally }) => ({ id: decision.id, result: tally.result })),
        minutesDocumentId: document.id,
      },
    });
    await writeAudit(tx, ctx, {
      action: 'assembly.hold', entityType: 'assembly', entityId: id, before: publicAssembly(claimed),
      after: {
        heldAt: heldAt.toISOString(), present: quorum.present, basisTotal: quorum.basisTotal,
        quorumReached: quorum.quorumReached, minutesDocumentId: document.id,
        decisions: tallies.map(({ decision, tally }) => ({ id: decision.id, result: tally.result })),
      },
    });
    return getAssembly(tx, ctx, id);
  });
}

  const buildingIds = await ownedBuildingIds(db, ctx, contactId);
  if (buildingIds.length === 0) return { rows: [] };
  const rows = await db.select({ a: A, buildingName: B.name }).from(A)
    .innerJoin(B, and(eq(B.id, A.buildingId), eq(B.tenantId, A.tenantId)))
    .where(and(eq(A.tenantId, ctx.tenantId), inArray(A.buildingId, buildingIds), inArray(A.status, [...VISIBLE_STATUSES])))
    .orderBy(desc(A.scheduledAt), desc(A.createdAt));
  return {
    rows: rows.map((r) => ({
      id: r.a.id, buildingId: r.a.buildingId, buildingName: r.buildingName, scheduledAt: r.a.scheduledAt,
      location: r.a.location, status: r.a.status as VisibleStatus, heldAt: r.a.heldAt,
      minutesDocumentId: r.a.minutesDocumentId, agendaCount: r.a.agenda.length,
    })),
  };
}

/** The three checks every portal read makes, applied to one assembly before anything is returned. */
async function visibleAssembly(db: Db, ctx: TenantContext, contactId: string, id: string) {
  const [row] = await db.select().from(A).where(and(eq(A.tenantId, ctx.tenantId), eq(A.id, id))).limit(1);
  if (!row || !VISIBLE_STATUSES.includes(row.status as VisibleStatus)) throw notFound('Assembly');
  await assertOwnsUnitIn(db, ctx, contactId, row.buildingId);
  return row;
}

export async function portalAssembly(db: Db, portal: PortalContext, contactIdParam: string, id: string) {
  const { ctx, contactId } = resolveLink(portal, contactIdParam);
  const row = await visibleAssembly(db, ctx, contactId, id);
  const [[building], decisions, mine] = await Promise.all([
    db.select({ name: B.name }).from(B).where(and(eq(B.tenantId, ctx.tenantId), eq(B.id, row.buildingId))).limit(1),
    db.select().from(AD).where(and(eq(AD.tenantId, ctx.tenantId), eq(AD.assemblyId, id))).orderBy(asc(AD.sortOrder), asc(AD.createdAt), asc(AD.id)),
    db.select().from(AV).where(and(eq(AV.tenantId, ctx.tenantId), eq(AV.assemblyId, id), eq(AV.contactId, contactId))),
  ]);
  const myChoice = new Map(mine.map((v) => [v.decisionId, v.choice]));
  const held = row.status === 'held';
  return {
    id: row.id, buildingId: row.buildingId, buildingName: building?.name ?? '',
    scheduledAt: row.scheduledAt, location: row.location, status: row.status as VisibleStatus,
    heldAt: row.heldAt, minutesDocumentId: row.minutesDocumentId, agenda: row.agenda,
    votingOpen: row.status === 'invited',
    decisions: decisions.map((d) => ({
      id: d.id, title: d.title, text: d.text, myChoice: myChoice.get(d.id) ?? null,
      // Nothing about the running tally leaks while the ballot is open (plan addendum 17).
      forWeight: held ? d.forWeight : null, againstWeight: held ? d.againstWeight : null,
      abstainWeight: held ? d.abstainWeight : null, presentWeight: held ? d.presentWeight : null,
      basisTotal: held ? d.basisTotal : null, quorumReached: held ? d.quorumReached : null,
      result: held ? d.result : null,
    })),
  };
}

/** The portal's only write (plan addendum 17): link, unit, window, then an upsert on the vote. */
export async function portalCastVote(db: Db, portal: PortalContext, contactIdParam: string, id: string, decisionId: string, choice: VoteChoice) {
  const { ctx, contactId } = resolveLink(portal, contactIdParam);
  await db.transaction(async (tx) => {
    const row = await visibleAssembly(tx, ctx, contactId, id);
    if (row.status !== 'invited') throw conflict('voting_closed', 'Voting on this assembly is closed');
    const [decision] = await tx.select({ id: AD.id }).from(AD)
      .where(and(eq(AD.tenantId, ctx.tenantId), eq(AD.assemblyId, id), eq(AD.id, decisionId))).limit(1);
    if (!decision) throw notFound('Decision');
    await upsertVote(tx, ctx, { assemblyId: id, decisionId, contactId, choice, via: 'portal' });
    // `ctx` here is the portal's read-only context: user id null, role `readonly` (spec §19.6).
    await writeAudit(tx, ctx, {
      action: 'assembly_vote.cast', entityType: 'assembly_decision', entityId: decisionId,
      after: { contactId, choice, via: 'portal' },
    });
  });
  return portalAssembly(db, portal, contactIdParam, id);
}

export async function portalAssemblyInvitation(db: Db, portal: PortalContext, contactIdParam: string, id: string) {
  const { ctx, contactId } = resolveLink(portal, contactIdParam);
  const row = await visibleAssembly(db, ctx, contactId, id);
  if (!row.invitationHtml) throw notFound('Assembly');
  return { html: row.invitationHtml, id: row.id };
}

  error.value = '';

**Four risks called out rather than hidden**

1. **The minutes PDF is rendered inside the hold transaction** (addendum 13). A slow Chrome holds a row lock for a second or two, and a dead Chrome makes holding an assembly impossible rather than merely undocumented. That is the deliberate trade: the alternative leaves `held` assemblies with no minutes, which is the worse failure for a compliance product. The only residue a crash can leave is an unreferenced file under `DATA_DIR`.
2. **`createDocument` inside an outer transaction becomes a savepoint, and its `store.put` is not transactional.** If the outer transaction rolls back after the file is written, the bytes stay on disk with no row pointing at them. Invisible and harmless, and the same residue the upload path can already leave; it is called out so nobody "fixes" it by moving the write outside the transaction, which would reintroduce risk 1's failure mode.
3. **The 15-day check and the compliance flag measure against different dates** — `scheduled_at` at invite time, `held_at` afterwards (addendum 8). They agree whenever the assembly happens when it was announced, which `holdAssembly`'s default `heldAt` makes the path of least resistance. A manager who invites punctually and then holds the assembly two weeks *early* would see a `late_invitation` flag that is, on the law's own reading, correct.
4. **Switching the compliance snapshot to the `assemblies` table changes what an existing tenant sees**, from "no assembly module, therefore `n/a`" to "one called assembly, therefore `due`". No tenant has an `assemblies` row before this migration, so the first screen after deploying is identical to the last one before it; the change only becomes visible once a manager schedules something, which is the intended behaviour.
