# Domar Compliance and Documents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A licensed manager opens a building and the first thing they see is the **Compliance** tab: one card per duty of the Law on Housing 160/2025, each with a colour, the article, the date of the last evidence, the next due date and a link that fixes it. The cards are computed from legal events the existing flows already write — publishing a period, sending or printing a reminder, the first owner linking to the portal — plus dates already in the system. From the same building the manager uploads the contract, the minutes and the supplier invoices; keeps a supplier list and the building's contracts (the management contract's end date starts the Art. 30 clock); and distributes an extraordinary cost (Art. 47(5)) that travels through the existing calculation engine, the existing generate/publish services and the existing ledger, so the owners get real invoices with real numbers and the reminder rules keep working on them. A tenant-wide `/app/compliance` page shows every building's worst status at a glance.

**Architecture:** `@domar/db` gains one migration (`0008`) and one schema file, `packages/db/src/schema/compliance.ts`: `legal_events` (append-only), `documents`, `suppliers`, `building_contracts`, plus three columns on existing tables (`expenses.supplier_id`, `expenses.document_id`, `billing_periods.kind`) and one more the extraordinary flow needs (`billing_periods.distribution_basis`). `@domar/domain` gains `src/compliance/evaluate.ts` — a pure `evaluateBuildingCompliance(snapshot, today, rules)` that turns a snapshot of dates and counts into eight duties with a worst-status summary — plus the thresholds (`complianceRules`) and the Macedonian labels (`labels.compliance`) on the country pack, and `localDayStart` on `src/period.ts`. `apps/api` gains `src/legal-events.ts` (the writer plus its readers), hooks in `resources/invoicing/publish.ts`, `resources/reminders/service.ts` and `portal/accounts.ts`, `src/documents/store.ts` (a `DocumentStore` interface with a local-disk driver behind `DATA_DIR`), and five resource folders: `resources/legal-events`, `resources/compliance`, `resources/documents`, `resources/suppliers`, `resources/contracts`, `resources/extraordinary`. `apps/web` gains a `compliance` tab (first, default) on the building page, a `/app/compliance` page, a `/app/suppliers` page, `documents`, `contracts` and `extraordinary` tabs, and supplier/document selects on the expense form. `e2e/tests/compliance.spec.ts` walks it end to end.

**Tech Stack:** unchanged (Node 24, pnpm 10, TS strict, Fastify 5 + zod, Drizzle 0.36 + Postgres 16, Vue 3 + Vite + vue-i18n + Tailwind 4, Vitest, Playwright 1.63.0) plus exactly one new package: `@fastify/multipart@^9.0.3` as a dependency of `@domar/api`. Everything else — hashing, streaming, directories — is `node:crypto`, `node:fs` and `node:stream`.

**Spec:** `docs/superpowers/specs/2026-09-24-domar-phase2-design.md` §1, §2 item 1, §3 (legal events and the compliance screen), §4 (documents, suppliers, contracts), §5 (extraordinary costs), §10 (roles), §11 (invariants). Phase 1: `docs/superpowers/specs/2026-09-21-domar-phase1-design.md` §16 (global constraints), §7 (ledger), §10 (auth and tenancy), §11 (API shape), §12 (web). Previous plans: `2026-09-24-07-import-migration.md` (this plan's style), `2026-09-24-05-reminders.md` (the reminder service this plan hooks), `2026-09-24-06-owner-portal.md` (`assertOwnsUnitIn`, the portal link this plan hooks).

## Global Constraints

From Phase 1 spec §16, verbatim:

- Node `>=24`, pnpm `>=10`, TypeScript strict, ESM only.
- Postgres 16; schema must run unchanged on Supabase Postgres (no superuser-only extensions; `pgcrypto`/`uuid-ossp` allowed).
- Every tenant-scoped table has `tenant_id uuid not null` and an index starting with it.
- Money columns: `bigint`, suffix `_minor`. Never `float`.
- All user-facing strings in the web app go through i18n; Macedonian first, English second.
- No secrets in the repo; `.env.example` documents every variable.
- Commit after every green test cycle; conventional commit messages.

Project conventions that are equally binding here:

- **Money is integer minor units** everywhere (`number` in TS, `bigint` in Postgres). Amounts on the wire end in `Minor`. The extraordinary cost's `amountMinor` arrives already in minor units and is never divided or multiplied on the way to the engine.
- **Tenant filter on every statement.** Every new repo function takes `(db, ctx, …)` and every `where` starts with `eq(X.tenantId, ctx.tenantId)`. No exceptions, including the document download and the portal document list.
- **An audit row is written inside the same transaction as every mutation** (`writeAudit(tx, ctx, …)`). A legal event is *not* a substitute for an audit row: the two are written side by side.
- **Role gating:** reads are behind `app.requireAuth` (every role, including `readonly`, may read compliance, documents, suppliers and contracts — spec §10); writes are behind `requireRole(...WRITE_ROLES)` (`owner`, `accountant`).
- **Error envelope:** `{ error: { code, message, details? } }` via `AppError`/`notFound`/`badRequest`/`conflict`. A row of another tenant is always `404`, never `403`.
- **TS strict with `exactOptionalPropertyTypes`**: never pass an explicit `undefined` into an object typed with an optional property; spread conditionally (`...(x ? { x } : {})`) or use `stripUndefined`.
- **ESM `.js` import specifiers** in every TS import of a local file (`./store.js`, `../../legal-events.js`), `import type` for type-only imports (`@typescript-eslint/consistent-type-imports` is an error).
- **i18n mk/en parity**: `apps/web/test/LoginPage.test.ts` asserts `flatKeys(messages.en).sort()` equals `flatKeys(messages.mk).sort()`. Every key added in this plan goes into both files, Macedonian first.
- **`data-test` hooks** on every element an e2e test touches (`testIdAttribute: 'data-test'` in `e2e/playwright.config.ts`).
- Run everything from the repo root. Postgres for tests is the docker-compose service on port 54329 (`pnpm db:up`).
- **Conventional commits**, each ending with your session's co-author trailer, e.g.
  ```
  Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
  ```

Phase 2 spec §11 invariants, verbatim, binding on every task here:

- Legal events are append-only and carry evidence; the compliance screen never reads anything but events plus dates already in the system.
- Every document download checks the tenant and, for portal users, the link (minutes and reports of their building only).
- Uploaded files are stored outside the web root, streamed, never executed, mime-checked, size-capped.
- Extraordinary costs and maintenance costs reach the ledger only through the existing period and expense flows; no new posting kinds.
- Notifications never include amounts in push payloads (title + link only); details load in the app. *(No notifications ship in this sub-plan; the constraint is recorded so nothing here invents a push payload.)*

## Design addendum (decisions not spelled out in the spec)

1. **`legal_events` is append-only by construction, not by convention.** `apps/api/src/legal-events.ts` exports exactly one writer (`recordLegalEvent`), one conditional writer (`recordLegalEventOnce`) and three readers. There is no `updateLegalEvent`, no `deleteLegalEvent`, and no route that mutates the table — only `GET /api/buildings/:id/legal-events`. Task 3's test asserts that `PATCH` and `DELETE` on that path answer `404`, so a future route cannot be added without a red test.
2. **Event evidence shapes, per kind** (the jsonb column is `{}`-defaulted and always an object):
   - `invoice_published` → `{ period: 'YYYY-MM', periodKind: 'regular' | 'extraordinary', invoiceCount: number, invoiceIds: string[], totalMinor: number }`, `refType: 'billing_period'`, `refId` = period id, `dueAt` = the invoices' due date.
   - `reminder_sent` → `{ contactId, channel: 'email' | 'letter', emailLogId: string | null, invoiceIds: string[], totalOutstandingMinor, reason: 'consecutive' | 'total' }`, `refType: 'reminder'`, `refId` = reminder id. `emailLogId` is the `email_log` row of the successful send; a printed letter carries `null` and `channel: 'letter'`.
   - `fund_statement_available` → `{ contactId, ownerAccountId }`, `refType: 'contact'`, `refId` = contact id. Written **once per building** (`recordLegalEventOnce`).
   - `extraordinary_cost_distributed` → `{ periodId, period, amountMinor, fund, distribution, appliesTo: string[], invoiceIds: string[], invoiceCount, documentId: string | null }`, `refType: 'billing_period'`, `refId` = the extraordinary period's id.
   - `assembly_invited`, `assembly_held`, `annual_report_issued`, `handover_report_issued` are in the enum but written by no code in this sub-plan. Their shapes are reserved as `{ documentId: string | null, … }` and the compliance evaluator already reads them, so sub-plans 2 and 3 light the cards up without touching the evaluator.
3. **Status vocabulary, one meaning across all eight duties.** `ok` — satisfied, the next deadline is in the future. `due` — the deadline has passed but a grace window is still open, so acting today is still defensible. `overdue` — the deadline and the grace window are both gone. `n/a` — the duty cannot apply to this building yet, and no amount of waiting will change that without new data. Worst-status ordering is `overdue` > `due` > `ok` > `n/a`.
4. **Thresholds live on the country pack** (`mkPack.complianceRules`), never in the evaluator: `invoiceMaxAgeDays: 35`, `reminderGraceDays: 30`, `assemblyMaxAgeMonths: 12`, `assemblyInvitationMinDays: 15`, `annualReportMaxAgeMonths: 12`, `handoverDays: 8`, `graceDays: 30`, `graceMonths: 3`. 35 days, not "one month", because a manager who bills on the 1st and again on the 5th of the following month is not late; `graceDays`/`graceMonths` are the generic windows that turn `due` into `overdue`.
5. **Per-duty rules, stated once so the tests and the implementation cannot drift.**
   - `invoices` (art. `19/33`): reference = `lastPublishedPeriodAt ?? buildingCreatedAt`; deadline = reference + 35 days; `ok` until the deadline, `due` for 30 days after it, `overdue` beyond.
   - `reminders` (art. `28`): `ok` when `ownersOverThreshold === 0`. Otherwise deadline = `oldestThresholdSince + 30 days` — the day the oldest still-unreminded owner crossed the Art. 28 threshold — `due` until it, `overdue` after.
   - `assembly` (art. `37`): `n/a` while `assemblyCount === 0` — the module does not exist yet, and a building that has never had an assembly under domar's watch must not be painted red on the strength of data domar does not have. With at least one assembly: `due` when none was ever held, otherwise deadline = `lastAssemblyHeldAt + 12 months`, `due` for 3 months after it, `overdue` beyond; and an otherwise-`ok` assembly whose invitation went out fewer than 15 days before it was held drops to `due` (the Art. 37 late-invitation flag).
   - `annual_report` (art. `31`): with no report ever, deadline = `buildingCreatedAt + 12 months` and the status is `n/a` until that date — a building three months old owes no annual report — then `due` for 3 months, then `overdue`. With a report, deadline = `lastAnnualReportAt + 12 months` and the same windows.
   - `fund_transparency` (art. `45(4)`): `ok` when at least one owner is linked to the portal **and** a `fund_statement_available` event exists; otherwise `due`. Never `overdue`: the law names no date.
   - `fund_accounts` (art. `42/45`): `ok` when both `regularFundAccount` and `reserveFundAccount` are non-empty after trimming; otherwise `overdue`. Not `due`: separate accounts are owed from the first day of the mandate, so an empty field is already a breach.
   - `handover` (art. `30`): `n/a` without a management contract end date. With one: `ok` while `today < endsOn` or a handover report was issued on/after `endsOn`; `due` from `endsOn` to `endsOn + 8 days`; `overdue` after.
   - `extraordinary_costs` (art. `47(5)`): always `n/a`, carrying `count` — informational, exactly as the spec says.
6. **`article` is a bare citation code, not a sentence.** The evaluator returns `'19/33'`, `'28'`, `'37'`, `'31'`, `'45(4)'`, `'42/45'`, `'30'`, `'47(5)'`; the web renders `t('compliance.article', { article })` → `чл. 45(4)` / `Art. 45(4)`. A pure function in a multi-country package has no business owning the Macedonian word for "article".
7. **`howToFix` is a relative deep link, the human sentence comes from the pack.** The evaluator returns a query string relative to the building page (`'?tab=periods'`, `'?tab=reminders'`, `'?tab=compliance#fund-accounts'`, `'?tab=contracts'`, `'?tab=extraordinary'`, `'?tab=units'`); the API merges `label` and `hint` from `pack.labels.compliance[key]` into each duty before it goes on the wire. The duty title and hint are therefore **always Macedonian** (the legal language of the pack), exactly like the reminder letter, while the chrome around them (status names, column headers, the word "article") is i18n'd. This is stated because it is the one place in the web app where a user-facing string does not come from `vue-i18n`.
8. **`today` is local midnight in the tenant's timezone.** `localDayStart(new Date(), tenant.timezone)` (new in `packages/domain/src/period.ts`, same two-pass offset resolution as `periodStartDate`) is what the API hands the evaluator. Every rule is day- or month-grained, so comparing against an instant in the middle of the day would make a duty flip status halfway through a working day.
9. **The compliance snapshot reads events for the things only events know and columns for the things columns know.** `lastPublishedPeriodAt` is `max(billing_periods.published_at)` — a column, so buildings published before this migration still count; `lastAssemblyHeldAt`, `lastAssemblyInvitedAt`, `lastAnnualReportAt`, `lastHandoverReportAt`, `fundStatementAvailableAt` and `extraordinaryCostCount` come from `legal_events`, because nothing else records them; `ownersOverThreshold` comes from the existing `overdueByOwner` + `evaluateOwner` + `priorRemindersByOwner` trio, so the compliance screen and the reminder job can never disagree; the two account numbers and `buildingCreatedAt` come from `buildings`; `managementContractEndsOn` is the `ends_on` of the newest `building_contracts` row of kind `management`.
10. **Document storage layout.** Files live under `DATA_DIR/documents/<tenantId>/<YYYY>/<documentId>.<ext>` and `documents.storage_key` holds that path relative to `DATA_DIR`. `DATA_DIR` defaults to `./data`, is git- and docker-ignored, and is a named volume (`domar-data`) in `docker-compose.prod.yml`. The key is generated by the API, never by the client, and `LocalDiskStore` re-validates it against `/^documents\/[0-9a-f-]{36}\/\d{4}\/[0-9a-f-]{36}\.[a-z0-9]{1,8}$/` on every read and delete, so a traversal attempt cannot leave the tree even if a key were ever forged into the database.
11. **Uploads and downloads are streamed, hashed on the way past, and capped twice.** `@fastify/multipart` is registered with `limits: { fileSize: 20 MiB, files: 1, fields: 8 }`; `LocalDiskStore.put` pipes the request stream through a `createHash('sha256')` transform into the destination file and returns `{ sizeBytes, sha256 }`, so the file is never buffered whole; after the pipe, `part.file.truncated` is checked and a truncated upload is deleted from disk and answered `413 file_too_large`. Downloads reply with `createReadStream`, the stored mime, `x-content-type-options: nosniff` and a `content-disposition` whose ASCII fallback is `filename="<sanitised>"` (every character outside `[A-Za-z0-9_.-]` replaced by `_`) plus `filename*=UTF-8''<encodeURIComponent(original)>` so a Cyrillic file name survives.
12. **The mime allowlist is a map from mime to extension**, so an unknown mime cannot produce a file without an extension: `application/pdf` → `pdf`, `image/png` → `png`, `image/jpeg` → `jpg`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document` → `docx`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` → `xlsx`, `text/csv` → `csv`, `text/plain` → `txt`. Anything else is `400 unsupported_media_type` before a byte is written.
13. **A document that something points at cannot be deleted.** `DELETE /api/documents/:id` refuses with `409 document_referenced` while a `building_contracts.document_id` or an `expenses.document_id` names it. The FKs are `on delete set null` so the database stays consistent if a row is ever removed another way, but the API's answer is the refusal, because a contract that silently loses its scan is worse than a failed delete.
14. **The portal sees `minutes` and `report` documents only, of buildings the contact owns a unit in.** `GET /api/portal/documents?contactId&buildingId` resolves the link with `resolveLink`, then `assertOwnsUnitIn` (both already exist), then filters `kind in ('minutes', 'report')`. `GET /api/portal/documents/:id/download?contactId` repeats the same three checks on the document's own building before it opens the file; a document with `building_id = null` (tenant-level) is never visible to the portal.
15. **The extraordinary period is a real `billing_period` of kind `extraordinary`, and the uniqueness rule becomes partial.** `billing_periods_building_period_idx` (unique on `(building_id, period)`) is replaced by `billing_periods_building_regular_period_idx`, unique on `(building_id, period)` **`where kind = 'regular'`**. One regular period per building per month is still guaranteed — the `period_exists` conflict test keeps passing — while a building can carry as many extraordinary periods in a month as it has extraordinary costs. The alternative the brief floated, a `2026-10-X1` suffix, was rejected: `period` is `char(7)` and is parsed by `isValidPeriod`, `monthsBetween` and `nextPeriod` in `@domar/domain` and joined on in five queries; widening it to carry a discriminator would spread the change across the whole codebase to buy nothing a partial index does not already give.
16. **The month an extraordinary cost lands in:** `period = the current month in the tenant's timezone`; if a **regular** period for that month exists and is already `published`, the next month is used instead (`nextPeriod`). The extraordinary period's own row is independent of the regular one, so this rule exists only so the owner does not receive a charge dated to a month they have already been invoiced and paid for.
17. **Distribution maps onto the engine without touching the engine.** The single manual line is always `pricing: 'shared_total'` with `unitPriceMinor = amountMinor` and `quantity: 1`, and the *basis* the engine splits by comes from a new nullable `billing_periods.distribution_basis` (`share_basis` enum): `share` → `custom` (the unit's `ownership_share`), `equal` → `equal`, `area` → `area`. `buildCalcInput` reads `period.distributionBasis ?? building.shareBasis` for `input.building.shareBasis`. Two lines in `generate.ts`, one nullable column, zero changes to `packages/domain/src/calculation/engine.ts` and therefore zero risk to the 2026-09 fixture's locked numbers. `fixed_per_unit` was rejected for `equal`: it charges each unit the stated price, so the building-wide total would be `price × unitCount` instead of the amount the manager typed.
18. **An extraordinary period never gets automatic lines.** It is inserted directly (not through `createPeriod`, which calls `buildAutoLines`), with `managementFeeMinor: 0`, and `buildCalcInput` skips the synthetic reserve-fund line when `period.kind === 'extraordinary'`. Without that guard a building with an active reserve fund would slip a monthly contribution into every extraordinary charge.
19. **The extraordinary flow is three sequential steps, not one transaction.** Create-the-period-and-its-line runs in its own transaction; `generatePeriod` and `publishPeriod` then run as they always do, each with its own transaction and its own row claim; the legal event is written in a fourth, tiny transaction once the invoice ids are known. Wrapping all four would mean re-implementing `generatePeriod` and `publishPeriod` against an outer `tx`, and the failure mode of the split — an extraordinary period left `open` or `generated` — is visible in the periods tab and fixable with the buttons that are already there.
20. **Numbering is untouched.** `publishPeriod` draws from `invoice_sequences` per tenant and year, so an extraordinary period's invoices simply take the next numbers in the tenant's single sequence. Nothing about `number_prefix`/`number_suffix` changes.
21. **`readonly` reads everything this plan adds.** Compliance, legal events, documents (including the download), suppliers and contracts are behind `app.requireAuth` alone; uploads, deletes, supplier and contract writes, and extraordinary costs are behind `requireRole(...WRITE_ROLES)`. Spec §10 says `readonly` sees compliance and reports; a compliance card whose evidence link 403s would be a card that lies.
22. **Task sizes.** The spec's eight bullets become ten tasks: the web work is split in two (the compliance screen; then documents, suppliers, contracts and the extraordinary form) because one web task would be ~1200 lines, and the e2e spec plus the deploy changes are the tenth.

 */
export function localDayStart(instant: Date, timeZone: string): Date {
  const [y, m, d] = new Intl.DateTimeFormat('en-CA', { timeZone, year: 'numeric', month: '2-digit', day: '2-digit' })
    .format(instant).split('-').map(Number);
  const guess = Date.UTC(y!, m! - 1, d!, 0, 0, 0);
  const candidate = guess - zoneOffsetAt(guess, timeZone);
  return new Date(guess - zoneOffsetAt(candidate, timeZone));
}

import type { ComplianceRules } from '../country/types.js';

export type ComplianceDutyKey =
  | 'invoices' | 'reminders' | 'assembly' | 'annual_report'
  | 'fund_transparency' | 'fund_accounts' | 'handover' | 'extraordinary_costs';

export type ComplianceStatus = 'ok' | 'due' | 'overdue' | 'n/a';

export const COMPLIANCE_DUTY_KEYS: readonly ComplianceDutyKey[] = [
  'invoices', 'reminders', 'assembly', 'annual_report', 'fund_transparency', 'fund_accounts', 'handover', 'extraordinary_costs',
];

/** Bare citation codes: the word "article" belongs to the UI's locale, not to a multi-country rule. */
const ARTICLES: Record<ComplianceDutyKey, string> = {
  invoices: '19/33', reminders: '28', assembly: '37', annual_report: '31',
  fund_transparency: '45(4)', fund_accounts: '42/45', handover: '30', extraordinary_costs: '47(5)',
};

/** Relative to the building page: the web prepends `/app/buildings/<id>`. */
const HOW_TO_FIX: Record<ComplianceDutyKey, string> = {
  invoices: '?tab=periods',
  reminders: '?tab=reminders',
  assembly: '?tab=compliance',
  annual_report: '?tab=compliance',
  fund_transparency: '?tab=units',
  fund_accounts: '?tab=compliance#fund-accounts',
  handover: '?tab=contracts',
  extraordinary_costs: '?tab=extraordinary',
};

/**
 * Dates and counts the API reads out of events and columns (spec §3, §11). Every timestamp is an ISO
 * string with an offset; `managementContractEndsOn` is a `YYYY-MM-DD` date, which parses as UTC
 * midnight — the same grain `today` is given in.
 */
export interface ComplianceSnapshot {
  buildingCreatedAt: string;
  lastPublishedPeriodAt: string | null;
  /** Owners the Art. 28 evaluation says are due a reminder right now. */
  ownersOverThreshold: number;
  /** When the oldest of those owners' oldest overdue invoice fell due. */
  oldestThresholdSince: string | null;
  lastReminderAt: string | null;
  assemblyCount: number;
  lastAssemblyHeldAt: string | null;
  lastAssemblyInvitedAt: string | null;
  lastAnnualReportAt: string | null;
  portalLinkedOwners: number;
  fundStatementAvailableAt: string | null;
  regularFundAccount: string | null;
  reserveFundAccount: string | null;
  /** `YYYY-MM-DD` from the newest management contract, or null when there is none. */
  managementContractEndsOn: string | null;
  lastHandoverReportAt: string | null;
  extraordinaryCostCount: number;

export interface ComplianceDuty {
  key: ComplianceDutyKey;
  article: string;
  status: ComplianceStatus;
  /** The deadline this status was decided against; null when the duty has no date. */
  dueAt: string | null;
  lastEvidenceAt: string | null;
  /** Query string relative to the building page. */
  howToFix: string;
  /** Owners waiting, owners linked, costs distributed — null when the duty counts nothing. */
  count: number | null;
}

export interface ComplianceResult {
  status: ComplianceStatus;
  duties: ComplianceDuty[];
  counts: { ok: number; due: number; overdue: number; na: number };
}

const DAY_MS = 86_400_000;
const parse = (s: string | null): Date | null => (s === null ? null : new Date(s));
const addDays = (d: Date, n: number): Date => new Date(d.getTime() + n * DAY_MS);
const wholeDaysBetween = (from: Date, to: Date): number => Math.floor((to.getTime() - from.getTime()) / DAY_MS);

/** Calendar months in UTC; the 31st of a month lands on the last day of a shorter one. */
function addMonths(d: Date, n: number): Date {
  const day = d.getUTCDate();
  const firstOfTarget = Date.UTC(d.getUTCFullYear(), d.getUTCMonth() + n, 1, d.getUTCHours(), d.getUTCMinutes(), d.getUTCSeconds(), d.getUTCMilliseconds());
  const t = new Date(firstOfTarget);
  const lastDay = new Date(Date.UTC(t.getUTCFullYear(), t.getUTCMonth() + 1, 0)).getUTCDate();
  t.setUTCDate(Math.min(day, lastDay));
  return t;
}

/** `ok` up to and including the deadline, `due` through the grace window, `overdue` after it. */
function windowStatus(deadline: Date, graceEnd: Date, today: Date): ComplianceStatus {
  if (today.getTime() <= deadline.getTime()) return 'ok';
  return today.getTime() <= graceEnd.getTime() ? 'due' : 'overdue';
}

function duty(key: ComplianceDutyKey, status: ComplianceStatus, dueAt: Date | null, lastEvidenceAt: string | null, count: number | null = null): ComplianceDuty {
  return { key, article: ARTICLES[key], status, dueAt: dueAt === null ? null : dueAt.toISOString(), lastEvidenceAt, howToFix: HOW_TO_FIX[key], count };
}

function invoicesDuty(s: ComplianceSnapshot, today: Date, r: ComplianceRules): ComplianceDuty {
  const ref = parse(s.lastPublishedPeriodAt) ?? new Date(s.buildingCreatedAt);
  const deadline = addDays(ref, r.invoiceMaxAgeDays);
  return duty('invoices', windowStatus(deadline, addDays(deadline, r.graceDays), today), deadline, s.lastPublishedPeriodAt);
}

function remindersDuty(s: ComplianceSnapshot, today: Date, r: ComplianceRules): ComplianceDuty {
  if (s.ownersOverThreshold === 0) return duty('reminders', 'ok', null, s.lastReminderAt, 0);
  const since = parse(s.oldestThresholdSince);
  if (since === null) return duty('reminders', 'due', null, s.lastReminderAt, s.ownersOverThreshold);
  const deadline = addDays(since, r.reminderGraceDays);
  return duty('reminders', today.getTime() <= deadline.getTime() ? 'due' : 'overdue', deadline, s.lastReminderAt, s.ownersOverThreshold);
}

function assemblyDuty(s: ComplianceSnapshot, today: Date, r: ComplianceRules): ComplianceDuty {
  // The assembly module arrives in sub-plan 2. Until a building has had one, domar knows nothing
  // about its assemblies and must not claim a breach it cannot evidence (plan addendum 5).
  if (s.assemblyCount === 0) return duty('assembly', 'n/a', null, null, 0);
  const held = parse(s.lastAssemblyHeldAt);
  if (held === null) return duty('assembly', 'due', null, s.lastAssemblyInvitedAt, s.assemblyCount);
  const deadline = addMonths(held, r.assemblyMaxAgeMonths);
  let status = windowStatus(deadline, addMonths(deadline, r.graceMonths), today);
  const invited = parse(s.lastAssemblyInvitedAt);
  // Art. 37: the invitation must go out at least 15 days before the assembly.
  if (status === 'ok' && invited !== null && wholeDaysBetween(invited, held) < r.assemblyInvitationMinDays) status = 'due';
  return duty('assembly', status, deadline, s.lastAssemblyHeldAt, s.assemblyCount);
}

function annualReportDuty(s: ComplianceSnapshot, today: Date, r: ComplianceRules): ComplianceDuty {
  const last = parse(s.lastAnnualReportAt);
  const deadline = addMonths(last ?? new Date(s.buildingCreatedAt), r.annualReportMaxAgeMonths);
  const graceEnd = addMonths(deadline, r.graceMonths);
  const status = windowStatus(deadline, graceEnd, today);
  // A building younger than a year owes no annual report yet; that is `n/a`, not a satisfied duty.
  if (last === null && status === 'ok') return duty('annual_report', 'n/a', deadline, null);
  return duty('annual_report', status, deadline, s.lastAnnualReportAt);
}

function fundTransparencyDuty(s: ComplianceSnapshot): ComplianceDuty {
  const ok = s.portalLinkedOwners > 0 && s.fundStatementAvailableAt !== null;
  // Never `overdue`: Art. 45(4) names a right, not a date.
  return duty('fund_transparency', ok ? 'ok' : 'due', null, s.fundStatementAvailableAt, s.portalLinkedOwners);
}

function fundAccountsDuty(s: ComplianceSnapshot): ComplianceDuty {
  const filled = (v: string | null) => v !== null && v.trim() !== '';
  // Not `due`: separate accounts are owed from the first day of the mandate, so a blank is a breach.
  return duty('fund_accounts', filled(s.regularFundAccount) && filled(s.reserveFundAccount) ? 'ok' : 'overdue', null, null);
}

function handoverDuty(s: ComplianceSnapshot, today: Date, r: ComplianceRules): ComplianceDuty {
  const endsOn = parse(s.managementContractEndsOn);
  if (endsOn === null) return duty('handover', 'n/a', null, s.lastHandoverReportAt);
  const deadline = addDays(endsOn, r.handoverDays);
  const issued = parse(s.lastHandoverReportAt);
  if (issued !== null && issued.getTime() >= endsOn.getTime()) return duty('handover', 'ok', deadline, s.lastHandoverReportAt);
  if (today.getTime() < endsOn.getTime()) return duty('handover', 'ok', deadline, null);
  return duty('handover', today.getTime() <= deadline.getTime() ? 'due' : 'overdue', deadline, null);
}

/**
 * Art. 47(5) is informational (spec §3): a distributed extraordinary cost is neither a duty met nor
 * a duty missed, it is a number the manager should be able to see.
 */
function extraordinaryDuty(s: ComplianceSnapshot): ComplianceDuty {
  return duty('extraordinary_costs', 'n/a', null, null, s.extraordinaryCostCount);
}

/**
 * Pure: the same snapshot, day and rules always give the same duties. `today` is local midnight in
 * the tenant's timezone (`localDayStart`), because every rule here is day- or month-grained.
 */
export function evaluateBuildingCompliance(snapshot: ComplianceSnapshot, today: Date, rules: ComplianceRules): ComplianceResult {
  const duties: ComplianceDuty[] = [
    invoicesDuty(snapshot, today, rules),
    remindersDuty(snapshot, today, rules),
    assemblyDuty(snapshot, today, rules),
    annualReportDuty(snapshot, today, rules),
    fundTransparencyDuty(snapshot),
    fundAccountsDuty(snapshot),
    handoverDuty(snapshot, today, rules),
    extraordinaryDuty(snapshot),
  ];
  const counts = { ok: 0, due: 0, overdue: 0, na: 0 };
  for (const d of duties) counts[d.status === 'n/a' ? 'na' : d.status] += 1;
  const status: ComplianceStatus = counts.overdue > 0 ? 'overdue' : counts.due > 0 ? 'due' : counts.ok > 0 ? 'ok' : 'n/a';
  return { status, duties, counts };
}

const LE = schema.legalEvents;

export type LegalEventRow = typeof LE.$inferSelect;

export interface NewLegalEvent {
  buildingId: string;
  kind: LegalEventKind;
  refType: string;
  refId?: string | null | undefined;
  occurredAt?: Date | undefined;
  dueAt?: Date | null | undefined;

/**
 * Spec §11: legal events are append-only. This module exports one writer, one conditional writer and
 * three readers — there is deliberately no update and no delete, and no route mutates the table.
 * Always called with the caller's transaction, so the event and the audit row commit together.

export async function recordLegalEvent(tx: Db, ctx: TenantContext, e: NewLegalEvent): Promise<LegalEventRow> {
  const [row] = await tx.insert(LE).values({
    tenantId: ctx.tenantId,
    buildingId: e.buildingId,

import { type Db, schema } from '@domar/db';
import {
  type ComplianceSnapshot, type CountryCode, evaluateBuildingCompliance, evaluateOwner,
  getCountryPack, localDayStart,
} from '@domar/domain';
import { and, asc, countDistinct, desc, eq, max, sql } from 'drizzle-orm';
import { countEvents, lastEventAt } from '../../legal-events.js';
import type { TenantContext } from '../../tenant-context.js';
import { getBuilding } from '../buildings/repo.js';
import { overdueByOwner, priorRemindersByOwner } from '../reminders/repo.js';

const B = schema.buildings; const BP = schema.billingPeriods; const BC = schema.buildingContracts;
const OCL = schema.ownerContactLinks; const U = schema.units; const R = schema.reminders; const T = schema.tenants;

/** One day wider than the 30-day suppression rule, exactly as `runBuildingReminders` reads it. */
const PRIOR_WINDOW_MS = 31 * 24 * 3600 * 1000;

async function tenantPack(db: Db, ctx: TenantContext) {
  const tenant = (await db.query.tenants.findFirst({ where: eq(T.id, ctx.tenantId) }))!;
  const pack = getCountryPack(tenant.countryCode as CountryCode);
  if (!pack) throw new Error(`unknown country pack: ${tenant.countryCode}`);
  return { tenant, pack };
}

/**
 * The Art. 28 half of the snapshot, computed with the very functions the nightly job uses, so the
 * compliance screen and the reminder run can never disagree about who is over the threshold.
 */
async function reminderState(db: Db, ctx: TenantContext, buildingId: string, now: Date, rules: ReturnType<typeof getCountryPack>['reminderRules']) {
  const overdue = await overdueByOwner(db, ctx, buildingId, now);
  const priors = await priorRemindersByOwner(db, ctx, buildingId, new Date(now.getTime() - PRIOR_WINDOW_MS));
  let ownersOverThreshold = 0;
  let oldestThresholdSince: number | null = null;
  for (const o of overdue) {
    const ev = evaluateOwner({ invoices: o.invoices, priorReminders: priors.get(o.contactId) ?? [] }, rules, now);
    if (!ev.due) continue;
    ownersOverThreshold += 1;
    for (const i of o.invoices) {
      const due = Date.parse(i.dueAt);
      if (oldestThresholdSince === null || due < oldestThresholdSince) oldestThresholdSince = due;
    }
  }
  const [lastRow] = await db.select({ sentAt: R.sentAt, createdAt: R.createdAt }).from(R)
    .where(and(eq(R.tenantId, ctx.tenantId), eq(R.buildingId, buildingId)))
    .orderBy(desc(sql`coalesce(${R.sentAt}, ${R.createdAt})`)).limit(1);
  return {
    ownersOverThreshold,
    oldestThresholdSince: oldestThresholdSince === null ? null : new Date(oldestThresholdSince).toISOString(),
    lastReminderAt: lastRow ? (lastRow.sentAt ?? lastRow.createdAt).toISOString() : null,
  };
}

/** Spec §11: nothing but legal events plus dates the system already holds. */
export async function buildComplianceSnapshot(db: Db, ctx: TenantContext, building: typeof B.$inferSelect, now: Date): Promise<ComplianceSnapshot> {
  const { pack } = await tenantPack(db, ctx);
  const [[published], [linked], [contract], reminders, assemblyCount, lastAssemblyHeldAt, lastAssemblyInvitedAt, lastAnnualReportAt, lastHandoverReportAt, fundStatementAvailableAt, extraordinaryCostCount] = await Promise.all([
    db.select({ at: max(BP.publishedAt) }).from(BP)
      .where(and(eq(BP.tenantId, ctx.tenantId), eq(BP.buildingId, building.id), eq(BP.status, 'published'))),
    db.select({ n: countDistinct(OCL.contactId) }).from(OCL)
      .innerJoin(U, and(eq(U.tenantId, OCL.tenantId), eq(U.ownerContactId, OCL.contactId)))
      .where(and(eq(OCL.tenantId, ctx.tenantId), eq(U.buildingId, building.id))),
    db.select({ endsOn: BC.endsOn }).from(BC)
      .where(and(eq(BC.tenantId, ctx.tenantId), eq(BC.buildingId, building.id), eq(BC.kind, 'management')))
      .orderBy(desc(BC.startsOn), desc(BC.createdAt)).limit(1),
    reminderState(db, ctx, building.id, now, pack.reminderRules),
    countEvents(db, ctx, building.id, 'assembly_held'),
    lastEventAt(db, ctx, building.id, 'assembly_held'),
    lastEventAt(db, ctx, building.id, 'assembly_invited'),
    lastEventAt(db, ctx, building.id, 'annual_report_issued'),
    lastEventAt(db, ctx, building.id, 'handover_report_issued'),
    lastEventAt(db, ctx, building.id, 'fund_statement_available'),
    countEvents(db, ctx, building.id, 'extraordinary_cost_distributed'),
  ]);
  return {
    buildingCreatedAt: building.createdAt.toISOString(),
    lastPublishedPeriodAt: published?.at ? published.at.toISOString() : null,
    ownersOverThreshold: reminders.ownersOverThreshold,
    oldestThresholdSince: reminders.oldestThresholdSince,
    lastReminderAt: reminders.lastReminderAt,
    assemblyCount,
    lastAssemblyHeldAt: lastAssemblyHeldAt?.toISOString() ?? null,
    lastAssemblyInvitedAt: lastAssemblyInvitedAt?.toISOString() ?? null,
    lastAnnualReportAt: lastAnnualReportAt?.toISOString() ?? null,
    portalLinkedOwners: Number(linked?.n ?? 0),
    fundStatementAvailableAt: fundStatementAvailableAt?.toISOString() ?? null,
    regularFundAccount: building.regularFundAccount,
    reserveFundAccount: building.reserveFundAccount,
    managementContractEndsOn: contract?.endsOn ?? null,
    lastHandoverReportAt: lastHandoverReportAt?.toISOString() ?? null,
    extraordinaryCostCount,
  };
}

/** The pack's Macedonian title and hint, merged onto the pure duties (plan addendum 7). */
function withLabels(result: ReturnType<typeof evaluateBuildingCompliance>, pack: ReturnType<typeof getCountryPack>) {
  return result.duties.map((d) => ({ ...d, label: pack.labels.compliance[d.key]?.title ?? d.key, hint: pack.labels.compliance[d.key]?.hint ?? '' }));
}

export async function buildingCompliance(db: Db, ctx: TenantContext, buildingId: string) {
  const building = await getBuilding(db, ctx, buildingId); // 404 across tenants
  const { tenant, pack } = await tenantPack(db, ctx);
  const now = new Date();
  const today = localDayStart(now, tenant.timezone);
  const snapshot = await buildComplianceSnapshot(db, ctx, building, now);
  const result = evaluateBuildingCompliance(snapshot, today, pack.complianceRules);
  return {
    building: { id: building.id, name: building.name },
    status: result.status,
    counts: result.counts,
    duties: withLabels(result, pack),
    evaluatedAt: today.toISOString(),
  };
}

/**
 * Every building of the tenant, worst status first-class. Sequential per building rather than one
 * clever join: a pilot tenant has tens of buildings, and the snapshot already shares its queries
 * with the reminder job, which is the correctness property worth keeping.
 */
export async function tenantCompliance(db: Db, ctx: TenantContext) {
  const { tenant, pack } = await tenantPack(db, ctx);
  const now = new Date();
  const today = localDayStart(now, tenant.timezone);
  const buildings = await db.select().from(B).where(eq(B.tenantId, ctx.tenantId)).orderBy(asc(B.name));
  const counts = { ok: 0, due: 0, overdue: 0, na: 0 };

import { createHash } from 'node:crypto';
import { createReadStream, createWriteStream } from 'node:fs';
import { mkdir, rm, stat } from 'node:fs/promises';
import { dirname, resolve, sep } from 'node:path';
import { Transform, type Readable } from 'node:stream';
import { pipeline } from 'node:stream/promises';

export const MAX_DOCUMENT_BYTES = 20 * 1024 * 1024;

/** Spec §4: the allowed mime list. A map, not a set, so an accepted file always gets an extension. */
export const ALLOWED_MIME: Readonly<Record<string, string>> = {
  'application/pdf': 'pdf',
  'image/png': 'png',
  'image/jpeg': 'jpg',
  'application/vnd.openxmlformats-officedocument.wordprocessingml.document': 'docx',
  'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet': 'xlsx',
  'text/csv': 'csv',
  'text/plain': 'txt',
};

/** `documents/<tenant uuid>/<year>/<document uuid>.<ext>` and nothing else may reach the disk. */
const KEY_RE = /^documents\/[0-9a-f-]{36}\/\d{4}\/[0-9a-f-]{36}\.[a-z0-9]{1,8}$/;

export function documentStorageKey(tenantId: string, documentId: string, mime: string, at: Date): string {
  const ext = ALLOWED_MIME[mime];
  if (!ext) throw new Error(`unsupported mime: ${mime}`);
  return `documents/${tenantId}/${at.getUTCFullYear()}/${documentId}.${ext}`;
}

/**
 * A Cyrillic file name survives in `filename*`; the ASCII `filename` is the fallback for clients
 * that ignore RFC 5987, and it is sanitised so a quote or a semicolon cannot break out of the header.
 */
export function contentDisposition(fileName: string, type: 'attachment' | 'inline' = 'attachment'): string {
  const ascii = fileName.replace(/[^A-Za-z0-9_.-]/g, '_') || 'document';
  return `${type}; filename="${ascii}"; filename*=UTF-8''${encodeURIComponent(fileName)}`;
}

export interface StoredFile { sizeBytes: number; sha256: string }

/** The seam an S3-compatible driver slots into later (spec §4); the API never touches `fs` directly. */
export interface DocumentStore {
  put(key: string, data: Readable): Promise<StoredFile>;
  open(key: string): Promise<Readable>;
  remove(key: string): Promise<void>;
}

export class LocalDiskStore implements DocumentStore {
  constructor(private readonly root: string) {}

  /** Two gates, on purpose: the shape of the key, and the resolved path staying inside the root. */
  private pathOf(key: string): string {
    if (!KEY_RE.test(key)) throw new Error(`invalid storage key: ${key}`);
    const root = resolve(this.root);
    const abs = resolve(root, key);
    if (!abs.startsWith(root + sep)) throw new Error(`storage key escapes the data directory: ${key}`);
    return abs;
  }

  /** Streams and hashes in one pass; nothing is buffered whole (spec §11). `wx` refuses to overwrite. */
  async put(key: string, data: Readable): Promise<StoredFile> {
    const abs = this.pathOf(key);
    await mkdir(dirname(abs), { recursive: true });
    const hash = createHash('sha256');
    let sizeBytes = 0;
    const meter = new Transform({
      transform(chunk: Buffer, _enc, cb) { hash.update(chunk); sizeBytes += chunk.length; cb(null, chunk); },
    });
    await pipeline(data, meter, createWriteStream(abs, { flags: 'wx', mode: 0o600 }));
    return { sizeBytes, sha256: hash.digest('hex') };
  }

  async open(key: string): Promise<Readable> {
    const abs = this.pathOf(key);
    await stat(abs); // throws before a reply is started, so a missing file is a 500 and not a broken stream
    return createReadStream(abs);
  }

  async remove(key: string): Promise<void> {
    await rm(this.pathOf(key), { force: true });
  }
}

export interface NewDocument {
  buildingId: string | null;
  kind: DocumentKind;
  title: string;
  fileName: string;
  mime: string;
  stream: Readable;
  /** Read *after* the stream is consumed: busboy only knows it hit the cap once it has. */
  isTruncated: () => boolean;

/**
 * The bytes land first and the row second, so a failed insert cannot leave a document without a
 * file; the reverse — a file without a row — is undone in the catch, so it cannot leave an orphan
 * either.
 */
export async function createDocument(db: Db, ctx: TenantContext, store: DocumentStore, input: NewDocument) {
  if (!ALLOWED_MIME[input.mime]) throw badRequest('unsupported_media_type', `Files of type ${input.mime} are not accepted`);
  const id = randomUUID();
  const now = new Date();
  const storageKey = documentStorageKey(ctx.tenantId, id, input.mime, now);
  const { sizeBytes, sha256 } = await store.put(storageKey, input.stream);
  if (input.isTruncated()) {
    await store.remove(storageKey);
    throw new AppError(413, 'file_too_large', `The file exceeds the ${MAX_DOCUMENT_BYTES} byte limit`);
  }
  if (sizeBytes === 0) {
    await store.remove(storageKey);
    throw badRequest('empty_file', 'The file is empty');
  }
  try {
    return await db.transaction(async (tx) => {
      const [row] = await tx.insert(D).values({
        id, tenantId: ctx.tenantId, buildingId: input.buildingId, kind: input.kind, title: input.title,
        fileName: input.fileName, mime: input.mime, sizeBytes, storageKey, sha256, uploadedBy: ctx.userId,
      }).returning();
      await writeAudit(tx, ctx, { action: 'document.create', entityType: 'document', entityId: row!.id, after: publicDocument(row!) });
      return publicDocument(row!);
    });
  } catch (err) {
    await store.remove(storageKey);
    throw err;
  }
}

/** Spec §4/addendum 13: a document a contract or an expense points at is not deletable. */

  const row = await getDocumentRow(db, ctx, id);

  const [expense] = await db.select({ id: E.id }).from(E).where(and(eq(E.tenantId, ctx.tenantId), eq(E.documentId, id))).limit(1);
  if (contract || expense) throw conflict('document_referenced', 'This document is attached to a contract or an expense');

import { and, asc, eq } from 'drizzle-orm';
import { writeAudit } from '../../audit.js';
import { badRequest, conflict, notFound } from '../../errors.js';
import type { TenantContext } from '../../tenant-context.js';
import { stripUndefined } from '../common.js';
import type { SupplierCreate, SupplierPatch } from './schema.js';

const S = schema.suppliers; const BC = schema.buildingContracts; const E = schema.expenses;

export async function assertSupplierInTenant(db: Db, ctx: TenantContext, id: string | null | undefined): Promise<void> {
  if (!id) return;
  const [row] = await db.select({ id: S.id }).from(S).where(and(eq(S.tenantId, ctx.tenantId), eq(S.id, id))).limit(1);
  if (!row) throw badRequest('invalid_reference', 'supplierId does not belong to this organization');
}

export async function getSupplier(db: Db, ctx: TenantContext, id: string) {
  const row = await db.query.suppliers.findFirst({ where: and(eq(S.tenantId, ctx.tenantId), eq(S.id, id)) });
  if (!row) throw notFound('Supplier');
  return row;
}

export async function listSuppliers(db: Db, ctx: TenantContext, includeInactive: boolean) {
  const rows = await db.select().from(S)
    .where(and(eq(S.tenantId, ctx.tenantId), ...(includeInactive ? [] : [eq(S.isActive, true)])))
    .orderBy(asc(S.name));
  return { rows };
}

export async function createSupplier(db: Db, ctx: TenantContext, input: SupplierCreate) {
  return db.transaction(async (tx) => {
    const [row] = await tx.insert(S).values({ ...stripUndefined(input), tenantId: ctx.tenantId, name: input.name }).returning();
    await writeAudit(tx, ctx, { action: 'supplier.create', entityType: 'supplier', entityId: row!.id, after: row });
    return row!;
  });
}

export async function updateSupplier(db: Db, ctx: TenantContext, id: string, patch: SupplierPatch) {
  return db.transaction(async (tx) => {
    const before = await getSupplier(tx, ctx, id);
    const [row] = await tx.update(S).set({ ...stripUndefined(patch), updatedAt: new Date() })
      .where(and(eq(S.tenantId, ctx.tenantId), eq(S.id, id))).returning();
    await writeAudit(tx, ctx, { action: 'supplier.update', entityType: 'supplier', entityId: id, before, after: row });
    return row!;
  });
}

export async function deleteSupplier(db: Db, ctx: TenantContext, id: string) {

function formatPeriod(d: Date, timeZone: string): string {
  return new Intl.DateTimeFormat('en-CA', { timeZone, year: 'numeric', month: '2-digit' }).format(d);
}

/**
 * This month, unless the building's *regular* period for it is already published — an owner should
 * not receive a charge dated to a month they have been invoiced and may already have paid for.
 */
export async function extraordinaryPeriodFor(db: Db, ctx: TenantContext, buildingId: string, timeZone: string, now: Date): Promise<string> {
  const current = formatPeriod(now, timeZone);
  const [regular] = await db.select({ status: BP.status }).from(BP)
    .where(and(eq(BP.tenantId, ctx.tenantId), eq(BP.buildingId, buildingId), eq(BP.period, current), eq(BP.kind, 'regular'))).limit(1);
  return regular?.status === 'published' ? nextPeriod(current) : current;
}

/**
 * Four steps, each with its own transaction (plan addendum 19): create the period and its single
 * line, generate through the existing engine, publish through the existing service — so the ledger,
 * the numbering and the reminder rules all behave exactly as they do for a regular month — and then
 * record the legal event with the invoice ids the publish produced.
 */
export async function distributeExtraordinaryCost(db: Db, ctx: TenantContext, buildingId: string, input: ExtraordinaryCostCreate) {
  await getBuilding(db, ctx, buildingId); // 404 across tenants
  const tenant = (await db.query.tenants.findFirst({ where: eq(T.id, ctx.tenantId) }))!;
  const now = new Date();
  const period = await extraordinaryPeriodFor(db, ctx, buildingId, tenant.timezone, now);

  const created = await db.transaction(async (tx) => {
    await assertDocumentInTenant(tx, ctx, input.documentId);
    const [row] = await tx.insert(BP).values({
      tenantId: ctx.tenantId, buildingId, period, kind: 'extraordinary',
      distributionBasis: BASIS[input.distribution], currency: tenant.currency,
      managementFeeMinor: 0, managementFeeAppliesTo: [],
    }).returning();
    await tx.insert(PL).values({
      tenantId: ctx.tenantId, periodId: row!.id, serviceId: null, description: input.description,
      pricing: 'shared_total', quantity: '1', unitPriceMinor: input.amountMinor, taxRateBp: 0,
      appliesTo: input.appliesTo ?? [], fund: input.fund, source: 'manual', sortOrder: 0,
      note: 'Вонреден трошок (чл. 47(5))',
    });
    await writeAudit(tx, ctx, {
      action: 'extraordinary_cost.create', entityType: 'billing_period', entityId: row!.id,
      after: { ...row!, amountMinor: input.amountMinor, distribution: input.distribution, fund: input.fund, documentId: input.documentId ?? null },
    });
    return row!;
  });

  const generated = await generatePeriod(db, ctx, buildingId, created.id);
  if (generated.invoiceCount === 0) {
    // Nothing to publish: undo the empty period rather than leaving it for the manager to find.
    await db.transaction(async (tx) => {
      await tx.delete(BP).where(and(eq(BP.tenantId, ctx.tenantId), eq(BP.id, created.id)));
      await writeAudit(tx, ctx, { action: 'extraordinary_cost.discard', entityType: 'billing_period', entityId: created.id, before: created });
    });
    throw badRequest('no_units', 'This distribution reaches no unit with an owner; check appliesTo and the unit shares');
  }

  const dueAt = new Date(now.getTime() + input.dueDays * 86_400_000);
  const published = await publishPeriod(db, ctx, buildingId, created.id, { dueAt });
  const invoices = await db.select({ id: INV.id }).from(INV)
    .where(and(eq(INV.tenantId, ctx.tenantId), eq(INV.periodId, created.id))).orderBy(asc(INV.id));
  const invoiceIds = invoices.map((i) => i.id);

  await db.transaction(async (tx) => {
    await recordLegalEvent(tx, ctx, {
      buildingId, kind: 'extraordinary_cost_distributed', refType: 'billing_period', refId: created.id,
      occurredAt: now, dueAt,
      evidence: {
        periodId: created.id, period, amountMinor: input.amountMinor, fund: input.fund,
        distribution: input.distribution, appliesTo: input.appliesTo ?? [],
        invoiceIds, invoiceCount: invoiceIds.length, documentId: input.documentId ?? null,
      },
    });
  });

  return { periodId: created.id, period, invoiceCount: published.invoiceCount, totalMinor: published.totalMinor, invoiceIds };
}
