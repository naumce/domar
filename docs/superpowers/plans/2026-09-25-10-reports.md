# Domar Reports (Art. 31, Art. 30) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A manager opens a building, picks a year and presses **Издај годишен извештај**. domar reads the year out of the ledger it has been keeping all along — the opening and closing cash of both funds, what was billed and what was collected, every expense by supplier, the works the reserve fund paid for, who still owes and how much, how many reminders went out, which assemblies were held and how many decisions they took — renders it as a PDF, files it as a `report` document the owners can download from the portal, and writes `annual_report_issued` with the figures as evidence. The Art. 31 card on the compliance screen turns green. When the management contract runs out, the same screen offers **Извештај за примопредавање**: the manager types the two bank balances, presses the button, and gets back two documents — the Art. 30 report (every owner's balance, every unpaid invoice, the ledger reconciled against the bank) and a zip with seven CSV files holding the units, the owners, the balances, the invoices, the payments, the expenses and the document index. `handover_report_issued` records both document ids, and the 8-day clock on the compliance screen stops. The two duties the manager used to owe a spreadsheet become two buttons with evidence behind them.

**Architecture:** `@domar/domain` gains `src/reports/annual.ts` and `src/reports/handover.ts` — two pure builders that turn ledger snapshots into a `fields` map plus the report's tables, so that when the RKD template arrives it is a template change and not an arithmetic change — plus a `reports` label group on the country pack. `apps/api` gains `resources/reports/{data,schema,service,export,routes}.ts` (tenant-scoped queries feeding the builders, the two issuing transactions, the zip export) and the two document templates `pdf/annual-report-html.ts` and `pdf/handover-report-html.ts`, built on the same shell and the same `escapeHtml` as the invoice and the minutes. One new dependency, `fflate`, zips the export in memory; `documents/store.ts` learns one extra mime (`application/zip`) that only server-generated documents may carry. **No new table:** a report *is* a document plus a legal event. `apps/web` gains a `reports` tab on the building page (`components/building/ReportsTab.vue`) and the two compliance deep links point at it. `e2e/tests/reports.spec.ts` walks a billed, part-paid building from the annual report to the handover zip.

**Tech Stack:** unchanged (Node 24, pnpm 10, TS strict, Fastify 5 + zod, Drizzle 0.36 + Postgres 16, Vue 3 + Vite + vue-i18n + Tailwind 4, Vitest, Playwright 1.63.0) **plus one runtime dependency in `apps/api`: `fflate@^0.8.2`** (Task 3). The PDF renderer (`pdf/html-to-pdf.ts`), the document store (`documents/store.ts`), `createDocumentFromBuffer` (`resources/documents/repo.ts`) and the legal-event writer (`legal-events.ts`) already exist and are reused.

**Spec:** `docs/superpowers/specs/2026-09-24-domar-phase2-design.md` §7 (reports — the binding section), §3 (the `annual_report` and `handover` duties, the `annual_report_issued` and `handover_report_issued` events), §4 (documents, contracts, the `ends_on` that drives the Art. 30 clock), §10 (roles: `readonly` sees compliance and reports), §11 (invariants). Phase 1: `docs/superpowers/specs/2026-09-21-domar-phase1-design.md` §16 (global constraints), §10 (auth and tenancy), §11 (API shape), §12 (web), §19 (the portal). Previous plans: `2026-09-25-09-assembly.md` (this plan's style, `createDocumentFromBuffer`, the render-inside-the-transaction pattern), `2026-09-24-08-compliance.md` (the legal-event writer, the compliance snapshot, the document store), `2026-09-24-07-import-migration.md` (the `;` CSV conventions).

## Global Constraints

From Phase 1 spec §16, verbatim:

- Node `>=24`, pnpm `>=10`, TypeScript strict, ESM only.
- Postgres 16; schema must run unchanged on Supabase Postgres (no superuser-only extensions; `pgcrypto`/`uuid-ossp` allowed).
- Every tenant-scoped table has `tenant_id uuid not null` and an index starting with it.
- Money columns: `bigint`, suffix `_minor`. Never `float`.
- All user-facing strings in the web app go through i18n; Macedonian first, English second.
- No secrets in the repo; `.env.example` documents every variable.
- Commit after every green test cycle; conventional commit messages.

Project conventions that are equally binding here:

- **Money is integer minor units** everywhere (`number` in TS, `bigint` in Postgres). Amounts on the wire end in `Minor`. This sub-plan adds **no money column and no table at all**; every amount it computes is a `number` of minor units derived from `postings.amount_minor`, and every field of a report that carries money ends in `Minor` including the keys of the `fields` map.
- **Tenant filter on every statement.** Every new repo function takes `(db, ctx, …)` and every `where` starts with `eq(X.tenantId, ctx.tenantId)`. No exceptions.
- **An audit row is written inside the same transaction as every mutation** (`writeAudit(tx, ctx, …)`). A legal event is *not* a substitute for an audit row: the two are written side by side.
- **Role gating:** reads are behind `app.requireAuth` (every role, `readonly` included, may read reports — spec §10); writes are behind `requireRole(...WRITE_ROLES)` (`owner`, `accountant`).
- **Error envelope:** `{ error: { code, message, details? } }` via `AppError`/`notFound`/`badRequest`/`conflict`. A row of another tenant is always `404`, never `403`.
- **TS strict with `exactOptionalPropertyTypes`**: never pass an explicit `undefined` into an object typed with an optional property; spread conditionally (`...(x ? { x } : {})`) or use `stripUndefined`.
- **ESM `.js` import specifiers** in every TS import of a local file (`./data.js`, `../../legal-events.js`), `import type` for type-only imports (`@typescript-eslint/consistent-type-imports` is an error).
- **i18n mk/en parity**: `apps/web/test/LoginPage.test.ts` asserts `flatKeys(messages.en).sort()` equals `flatKeys(messages.mk).sort()`. Every key added in this plan goes into both files, Macedonian first.
- **`data-test` hooks** on every element an e2e test touches (`testIdAttribute: 'data-test'` in `e2e/playwright.config.ts`).
- Run everything from the repo root. Postgres for tests is the docker-compose service on port 54329 (`pnpm db:up`).
- **Conventional commits**, each ending with your session's co-author trailer, e.g.
  ```
  Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
  ```

Phase 2 spec §11 invariants, verbatim, binding on every task here:

- Legal events are append-only and carry evidence; the compliance screen never reads anything but events plus dates already in the system.
- Every document download checks the tenant and, for portal users, the link (minutes and reports of their building only).
- Uploaded files are stored outside the web root, streamed, never executed, mime-checked, size-capped.
- Extraordinary costs and maintenance costs reach the ledger only through the existing period and expense flows; no new posting kinds.
- Notifications never include amounts in push payloads (title + link only); details load in the app. *(No push notification ships in this sub-plan; the constraint is recorded so nothing here invents one. A report reaches an owner as a document in the portal list, which is a full page, not a payload-limited push.)*

## Design addendum (decisions not spelled out in the spec)

1. **A report is a document plus a legal event. No `reports` table.** Everything a `reports` row would hold is already held somewhere better: the file and its sha256 in `documents`, the moment and the figures in `legal_events.evidence` (append-only, which is exactly what a filed report should be), the building in both. A table would add a third place to keep the same truth and a fourth way for the three to disagree. `GET /buildings/:id/reports` is therefore the join of `legal_events` (kinds `annual_report_issued`, `handover_report_issued`) onto `documents`, newest first, plus the plain list of `report`-kind documents of the building, so a report somebody uploaded by hand is visible next to the ones domar generated. **This decision is recorded here because the brief asked for it explicitly: no migration is written in this sub-plan.**
2. **The arithmetic is a pure domain function; the API only fetches.** `packages/domain/src/reports/annual.ts` exports `buildAnnualReport(input): AnnualReportData` and nothing in it touches a database, a clock or a locale. That is what makes the exact minor sums testable as literals (Task 1) and what makes the RKD template, when it arrives, a change to `pdf/annual-report-html.ts` alone.
3. **The output is one flat `fields` map plus typed tables.** `AnnualReportData.fields` is a `Record<string, string | number>` holding every scalar the template prints as a labelled value (`billedMinor`, `regularClosingMinor`, `debtorsCount`, `collectionRateBp`, …), and the tables (`funds`, `expenses`, `expensesBySupplier`, `works`, `owners`, `debtors`, `assemblies`) are typed arrays beside it. Spec §7's "template fields kept in a single map" is the `fields` map; a table is not a field, and flattening one into string keys would be a worse map, not a fuller one.
4. **"Works done" is what the reserve fund paid for.** `expenses` has no `category` column and inventing one for this report would be a migration in service of a word. Art. 45 makes the reserve fund the fund that pays for maintenance and repair of the common parts, so `works = expenses.filter((e) => e.fund === 'reserve')`, listed by supplier and description with the amount and the date, and `fields.worksCount`/`fields.worksMinor` summarise them. Every expense, of either fund, is still listed in full in `expenses` and grouped in `expensesBySupplier`, so nothing is hidden by the choice — it only decides which subset gets the heading "Изведени работи".
5. **Fund cash is `account = 'fund'`, and it is the only thing that balances.** Owner charges never touch a fund posting (`resources/invoicing/publish.ts` posts them to `account 'owner'` only), so a fund's movement in a window is exactly its cash: payments in, expenses out, an `opening_balance` posting in, an `expense_void` adjustment back in. Hence the invariant the tests lock: **`openingMinor + inflowMinor − outflowMinor === closingMinor` for each fund**, where `openingMinor` is `Σ amount_minor` over that building's fund postings booked *strictly before* the window and `inflow`/`outflow` split the window's postings by sign.
6. **Movements arrive grouped, not raw.** The builder's input carries `fundMovements: { fund, kind, refType, inflowMinor, outflowMinor }[]` rather than one entry per posting, because the SQL that produces them is a `group by fund, kind, ref_type` with two conditional sums, and a building with four years of payments has tens of thousands of postings and six movement rows. Splitting inflow from outflow inside the group is what keeps the grouping lossless: a `(kind, refType)` pair that ever carried both signs would otherwise net out and the report would understate both sides.
7. **Billed and collected are read off owner postings, not off invoices.** `billedMinor` is `Σ` of `kind = 'charge'` owner postings inside the window; `collectedMinor` is `−Σ` of owner postings whose `ref_type` is `'payment'` or `'payment_void'` (a payment posts a negative to the owner, its void posts the same amount back, so a voided payment nets to exactly zero). Reading invoices instead would miss opening balances, adjustments and any payment not bound to an invoice, all of which the ledger already has right.
8. **The window is the tenant's civil year, not UTC.** `yearWindow(2026, 'Europe/Skopje')` is `[2025-12-31T23:00:00.000Z, 2026-12-31T23:00:00.000Z)` — local midnight to local midnight, resolved through `localDayStart`, the same function the compliance evaluator uses for `today`. A payment booked at 00:30 on 1 January in Skopje belongs to the new year on every screen domar has, and this one must not be the exception. `from` is inclusive, `to` is exclusive.
9. **The handover window is the current civil year up to and including `asOf`.** `asOfWindow('2026-09-30', 'Europe/Skopje')` is `[2026-01-01 local, 2026-10-01 local)`. Spec §7 says "the same data up to the contract end date"; the only question it leaves open is where the window *starts*, and the year it ends in is the only answer that makes the handover report readable next to the last annual report — the two together cover every day of the mandate without overlap.
10. **Bank balances are input, and the difference is printed.** `POST …/handover` takes `bankBalances: { regularMinor, reserveMinor }`, the manager's reading of the two statements. The report prints, per fund, the ledger closing, the bank balance and `differenceMinor = bank − ledger`. domar does not correct either number and does not refuse a difference: a handover report that hides a discrepancy is worse than one that names it, and naming it is what lets the incoming manager ask the question. The values are audited in full (`writeAudit`) and stamped into the event's evidence. The preview endpoint defaults them to the ledger closing, so an unfilled form previews as a reconciled one rather than as a fake shortfall.
11. **The export zip is built in memory with `fflate@^0.8.2` and filed as a second document.** `fflate` is dependency-free, ships its own types, and `zipSync(files, { level: 6 })` is the whole API this needs — `archiver` and `yazl` are stream-oriented and would drag in six transitive packages to write seven files that together weigh kilobytes. Seven CSVs, named in Macedonian transliteration so the incoming manager can read the archive without a manifest: `edinici.csv` (units), `sopstvenici.csv` (owners), `salda.csv` (balances), `presmetki.csv` (invoices), `uplati.csv` (payments), `troshoci.csv` (expenses), `dokumenti.csv` (the document index — metadata only, never the bytes). Each file is UTF-8 **with a BOM** and `;`-separated with `\n` line endings, exactly the shape `packages/domain/src/import/serialize.ts` writes and `ImportTab.vue` downloads, so the export of one building opens in Excel and re-imports into the next manager's system.
12. **`application/zip` is allowed for generated documents only.** `ALLOWED_MIME` in `documents/store.ts` stays exactly as it is — it is the upload allowlist and an uploaded zip is an executable-shaped blob nobody asked for. A second map `GENERATED_MIME = { ...ALLOWED_MIME, 'application/zip': 'zip' }` is what `createDocumentFromBuffer` passes as `input.allow`, and `createDocument` checks `input.allow ?? ALLOWED_MIME`. The multipart route never sets `allow`, so there is no code path from an HTTP upload to a stored zip. The export document's `kind` is `other`, not `report`: the portal shows `minutes` and `report` to owners, and the full data export of a building is for the incoming manager, not for a resident.
13. **Issuing is one transaction, PDF included, and the whole thing rolls back if Chrome is unavailable.** Exactly the shape `holdAssembly` already has: render the HTML, render the PDF, file the document(s), write the legal event, write the audit row — all inside `db.transaction`. `htmlToPdf` throwing gives the caller `503 pdf_unavailable` and nothing is filed. If anything after the document insert throws, the catch removes the stored bytes, because `createDocument`'s own cleanup only covers *its own* failure and a file with no row is an orphan nothing reaches.
14. **Re-issuing the same year is a new version, not an error.** A manager who fixes an expense and re-issues the 2026 report gets a second document and a second `annual_report_issued` event; nothing is overwritten, because an event log you may rewrite is not evidence. `GET /buildings/:id/reports` lists newest first, and the compliance duty reads `lastEventAt`, which already orders by `occurred_at desc, seq desc` — so the latest version is the one that counts, and the earlier one stays downloadable.
15. **`occurred_at` is the moment of issuing, for both events.** Not the year, not `asOf`. The Art. 31 clock in `annualReportDuty` measures twelve months from the last report *being issued*, and the Art. 30 rule in `handoverDuty` asks whether a report was issued at or after the contract's end date; both read `occurred_at`, and both are right only if it means "when the manager did this". The year and the `asOf` live in the evidence, where they belong.
16. **The compliance snapshot is not changed — it is verified.** `resources/compliance/snapshot.ts` already fills `lastAnnualReportAt` from `lastEventAt(db, ctx, building.id, 'annual_report_issued')` and `lastHandoverReportAt` from `lastEventAt(…, 'handover_report_issued')`, and `managementContractEndsOn` from the newest `management` contract. This sub-plan makes those two events exist for the first time; Tasks 2 and 3 each assert the duty flips through the API, and **no line of `snapshot.ts` or of `packages/domain/src/compliance/evaluate.ts`'s rules is edited**. The one thing that does change is cosmetic: both duties' `howToFix` moves to `?tab=reports` in Task 4, once the tab exists.
17. **Handover without a management contract is allowed and stays `n/a`.** `POST …/handover` does not require a `management` contract with an `ends_on`; it records whatever it finds (`contractEndsOn: string | null`) in the evidence and on the report. A manager handing a building over early, or one whose contract end was never entered, still gets the report and the export. The Art. 30 card meanwhile stays `n/a` — because `handoverDuty` returns `n/a` when `managementContractEndsOn` is null, and a duty with no date cannot be discharged on time or late. That is the honest reading, and the card's hint already tells the manager to record the contract.
18. **`asOf` may not be in the future.** `400 as_of_in_the_future`. Everything the handover report says about the money is read out of a ledger that ends today; dating it forward would print today's numbers under tomorrow's heading.
19. **The portal gets no new route.** `portalDocuments` already filters on `kind in ('minutes','report')` and already scopes to a building the contact owns a unit in, so both reports appear in the owner's document list the moment they are filed and download through the existing `GET /api/portal/documents/:id/download?contactId=…`. A `GET /portal/reports` would be that same query with one value of one filter pinned — a second surface to keep tenant-safe in exchange for nothing. Task 2 asserts the portal actually sees the filed annual report, through the existing route, rather than asserting the constant that lets it. `PortalFundPage.vue` is untouched: the fund page shows the live balance, and the annual report is a document, not a balance.
20. **Task sizes.** Five tasks: the domain builders and the pack labels; the API's data layer plus the annual report end to end; the handover with its zip; the manager's screen; the walk-through. Tasks 2 and 3 are the two big ones (~600 lines each including their tests) and split at the natural seam — Task 2 builds every shared query in `data.ts` and spends them on Art. 31, Task 3 adds one window, one template, one zip and Art. 30 on top.

import { localDayStart } from '../period.js';

export type ReportFund = 'regular' | 'reserve';
/** The `postings.kind` labels; a report never invents one (spec §11). */
export type ReportPostingKind = 'charge' | 'payment' | 'expense' | 'adjustment' | 'opening';

/** `from` inclusive, `to` exclusive; both are UTC instants of local midnight in the tenant's zone. */
export interface ReportWindow { from: Date; to: Date }

/**
 * A `YYYY-MM-DD` string onto the UTC instant of local midnight of that civil day in `timeZone`.
 * Anchored at noon UTC before the zone is applied, so the civil day read back out is never pushed a
 * day either way by the offset — the same trick `compliance/evaluate.ts` plays on a contract's end.
 */
export function civilDayStart(dateOnly: string, timeZone: string): Date {
  return localDayStart(new Date(`${dateOnly}T12:00:00.000Z`), timeZone);
}

/** The tenant's civil year: local midnight on 1 January to local midnight on the next 1 January. */
export function yearWindow(year: number, timeZone: string): ReportWindow {
  return { from: civilDayStart(`${year}-01-01`, timeZone), to: civilDayStart(`${year + 1}-01-01`, timeZone) };
}

/** One `(fund, kind, refType)` group of fund-account postings inside the window (plan addendum 6). */
export interface FundMovementIn {
  fund: ReportFund;
  kind: ReportPostingKind;
  refType: string;
  /** Σ of the group's positive amounts. */
  inflowMinor: number;
  /** Σ of the absolute value of the group's negative amounts. */
  outflowMinor: number;

const FUNDS: readonly ReportFund[] = ['regular', 'reserve'];

function summariseFund(fund: ReportFund, openingMinor: number, movements: FundMovementIn[]): FundSummary {
  const byKey = new Map<string, FundMovement>();
  let inflowMinor = 0;
  let outflowMinor = 0;
  for (const m of movements) {
    if (m.fund !== fund) continue;
    inflowMinor += m.inflowMinor;
    outflowMinor += m.outflowMinor;
    const key = `${m.kind}|${m.refType}`;
    const e = byKey.get(key) ?? { kind: m.kind, refType: m.refType, inflowMinor: 0, outflowMinor: 0, netMinor: 0 };
    e.inflowMinor += m.inflowMinor;
    e.outflowMinor += m.outflowMinor;
    e.netMinor = e.inflowMinor - e.outflowMinor;
    byKey.set(key, e);
  }
  const rows = [...byKey.values()].sort((a, b) => a.kind.localeCompare(b.kind) || a.refType.localeCompare(b.refType));
  return { fund, openingMinor, inflowMinor, outflowMinor, closingMinor: openingMinor + inflowMinor - outflowMinor, movements: rows };
}

/**
 * Art. 31, one building, one window. Pure: the same input always gives the same report, which is
 * what makes the figures on a filed PDF reproducible years later from the event's evidence.
 */
export function buildAnnualReport(input: AnnualReportInput): AnnualReportData {
  const funds = FUNDS.map((f) => summariseFund(f, input.opening[f] ?? 0, input.fundMovements));
  const regular = funds[0]!;
  const reserve = funds[1]!;

  const expenses = [...input.expenses].sort((a, b) => a.paidAt.localeCompare(b.paidAt) || a.id.localeCompare(b.id));
  const bySupplier = new Map<string, SupplierTotal>();
  for (const e of expenses) {
    const t = bySupplier.get(e.supplier) ?? { supplier: e.supplier, count: 0, amountMinor: 0 };
    t.count += 1;
    t.amountMinor += e.amountMinor;
    bySupplier.set(e.supplier, t);
  }
  const expensesBySupplier = [...bySupplier.values()].sort((a, b) => b.amountMinor - a.amountMinor || a.supplier.localeCompare(b.supplier));
  const works = expenses.filter((e) => e.fund === 'reserve');

  const owners = [...input.owners].sort((a, b) => a.name.localeCompare(b.name) || a.contactId.localeCompare(b.contactId));
  const debtors: DebtorRow[] = owners
    .filter((o) => o.balanceMinor > 0)
    .map((o) => ({ contactId: o.contactId, name: o.name, unitLabels: o.unitLabels, balanceMinor: o.balanceMinor }))
    .sort((a, b) => b.balanceMinor - a.balanceMinor || a.name.localeCompare(b.name));

  const billedMinor = owners.reduce((s, o) => s + o.billedMinor, 0);
  const collectedMinor = owners.reduce((s, o) => s + o.collectedMinor, 0);
  const expensesMinor = expenses.reduce((s, e) => s + e.amountMinor, 0);
  const worksMinor = works.reduce((s, e) => s + e.amountMinor, 0);
  const totalDebtMinor = debtors.reduce((s, d) => s + d.balanceMinor, 0);
  const assemblies = [...input.assemblies].sort((a, b) => a.heldAt.localeCompare(b.heldAt));

  return {
    fields: {
      year: input.year,
      periodFrom: input.window.from,
      periodTo: input.window.to,
      buildingName: input.building.name,
      buildingAddress: `${input.building.address}, ${input.building.postalCode} ${input.building.city}`,
      managerName: input.manager.name,
      managerCompanyNumber: input.manager.companyNumber ?? '',
      unitCount: input.building.unitCount,
      ownerCount: owners.length,
      regularOpeningMinor: regular.openingMinor,
      regularInflowMinor: regular.inflowMinor,
      regularOutflowMinor: regular.outflowMinor,
      regularClosingMinor: regular.closingMinor,
      reserveOpeningMinor: reserve.openingMinor,
      reserveInflowMinor: reserve.inflowMinor,
      reserveOutflowMinor: reserve.outflowMinor,
      reserveClosingMinor: reserve.closingMinor,
      billedMinor,
      collectedMinor,
      expensesMinor,
      // Basis points, like every other rate in this codebase, and integer-rounded half up so the
      // printed percentage never drifts from the two numbers printed beside it.
      collectionRateBp: billedMinor === 0 ? 0 : divRoundHalfUp(collectedMinor * 10_000, billedMinor),
      debtorsCount: debtors.length,
      totalDebtMinor,
      remindersSent: input.remindersSent,
      assembliesHeld: assemblies.length,
      decisionsTaken: assemblies.reduce((s, a) => s + a.decisionCount, 0),
      worksCount: works.length,
      worksMinor,
    },
    funds,
    expenses,
    expensesBySupplier,
    works,
    owners,
    debtors,
    assemblies,
  };
}

import { localDayStart } from '../period.js';
import {
  buildAnnualReport, civilDayStart,
  type AnnualReportData, type AnnualReportInput, type ReportFund, type ReportOwner, type ReportWindow,
} from './annual.js';

const DAY_MS = 86_400_000;

/**
 * Art. 30: the civil year up to and including `asOf` (plan addendum 9). The exclusive end is local
 * midnight of the day *after* `asOf`, resolved through the zone a second time so the last day of the
 * window is 23 or 25 hours long across a DST change rather than a flat 24.
 */
export function asOfWindow(asOf: string, timeZone: string): ReportWindow {
  const year = Number(asOf.slice(0, 4));
  const nextDay = new Date(Date.parse(`${asOf}T12:00:00.000Z`) + DAY_MS);
  return { from: civilDayStart(`${year}-01-01`, timeZone), to: localDayStart(nextDay, timeZone) };
}

export interface HandoverReportInput extends AnnualReportInput {
  /** `YYYY-MM-DD`, the day the mandate ends. */
  asOf: string;
  /** `building_contracts.ends_on` of the newest management contract, or null when there is none. */
  contractEndsOn: string | null;
  openItems: OpenItem[];
  bankBalances: BankBalances;
  note: string | null;

export interface FundReconciliation { fund: ReportFund; ledgerMinor: number; bankMinor: number; differenceMinor: number }

export interface HandoverReportData {
  fields: Record<string, string | number>;
  annual: AnnualReportData;
  /** Every owner with what they were billed, what they paid and where they stand — not only debtors. */
  owners: ReportOwner[];
  openItems: OpenItem[];
  reconciliation: FundReconciliation[];
}

/**
 * Art. 30. The annual arithmetic of the year so far, plus the three things a handover adds: every
 * owner's balance, every unpaid invoice, and the ledger measured against the bank. The difference is
 * printed, never corrected and never suppressed (plan addendum 10).
 */
export function buildHandoverReport(input: HandoverReportInput): HandoverReportData {
  const annual = buildAnnualReport(input);
  const openItems = [...input.openItems].sort((a, b) =>
    b.outstandingMinor - a.outstandingMinor || a.ownerName.localeCompare(b.ownerName) || a.invoiceId.localeCompare(b.invoiceId));
  const bank: Record<ReportFund, number> = { regular: input.bankBalances.regularMinor, reserve: input.bankBalances.reserveMinor };
  const reconciliation: FundReconciliation[] = annual.funds.map((f) => ({
    fund: f.fund, ledgerMinor: f.closingMinor, bankMinor: bank[f.fund], differenceMinor: bank[f.fund] - f.closingMinor,
  }));
  return {
    fields: {
      ...annual.fields,
      asOf: input.asOf,
      contractEndsOn: input.contractEndsOn ?? '',
      note: input.note ?? '',
      bankAsOf: input.bankBalances.asOf,
      bankRegularMinor: bank.regular,
      bankReserveMinor: bank.reserve,
      regularDifferenceMinor: reconciliation[0]!.differenceMinor,
      reserveDifferenceMinor: reconciliation[1]!.differenceMinor,
      openItemsCount: openItems.length,
      openItemsMinor: openItems.reduce((s, i) => s + i.outstandingMinor, 0),
    },
    annual,
    owners: annual.owners,
    openItems,
    reconciliation,
  };
}

import { type Db, schema } from '@domar/db';
import {
  buildAnnualReport, getCountryPack, yearWindow,
  type AnnualReportInput, type CountryCode, type CountryPack, type FundMovementIn,
  type ReportAssembly, type ReportExpense, type ReportFund, type ReportOwner, type ReportPostingKind,
} from '@domar/domain';
import { and, asc, count, eq, gte, inArray, isNull, lt, sql } from 'drizzle-orm';
import type { TenantContext } from '../../tenant-context.js';
import { getBuilding } from '../buildings/repo.js';

const P = schema.postings; const E = schema.expenses; const S = schema.suppliers; const U = schema.units;
const C = schema.contacts; const R = schema.reminders; const AS = schema.assemblies; const AD = schema.assemblyDecisions;
const T = schema.tenants;

export type BuildingRow = Awaited<ReturnType<typeof getBuilding>>;
export type TenantRow = typeof T.$inferSelect;

/**
 * The tenant row and its pack, kept locally exactly as `resources/compliance/snapshot.ts` keeps one:
 * a report reads the pack for its legal sentences and its money format, nothing more.
 */
export async function tenantPack(db: Db, ctx: TenantContext) {
  const tenant = (await db.query.tenants.findFirst({ where: eq(T.id, ctx.tenantId) }))!;
  const pack = getCountryPack(tenant.countryCode as CountryCode);
  if (!pack) throw new Error(`unknown country pack: ${tenant.countryCode}`);
  return { tenant, pack };
}

/** Fund cash before the window opens. A fund with no history is 0, never absent (addendum 5). */
async function openingByFund(db: Db, ctx: TenantContext, buildingId: string, from: Date): Promise<Record<ReportFund, number>> {
  const rows = await db.select({ fund: P.fund, total: sql<string>`coalesce(sum(${P.amountMinor}), 0)` }).from(P)
    .where(and(eq(P.tenantId, ctx.tenantId), eq(P.buildingId, buildingId), eq(P.account, 'fund'), lt(P.bookedAt, from)))
    .groupBy(P.fund);
  const out: Record<ReportFund, number> = { regular: 0, reserve: 0 };
  for (const r of rows) out[r.fund as ReportFund] = Number(r.total);
  return out;
}

/**
 * Fund cash moved inside the window, grouped the way the report prints it. Inflow and outflow are
 * summed separately inside each group so the grouping is lossless even if a `(kind, refType)` pair
 * ever carries both signs (addendum 6).
 */
async function fundMovements(db: Db, ctx: TenantContext, buildingId: string, from: Date, to: Date): Promise<FundMovementIn[]> {
  const rows = await db.select({
    fund: P.fund, kind: P.kind, refType: P.refType,
    inflow: sql<string>`coalesce(sum(case when ${P.amountMinor} > 0 then ${P.amountMinor} else 0 end), 0)`,
    outflow: sql<string>`coalesce(sum(case when ${P.amountMinor} < 0 then -${P.amountMinor} else 0 end), 0)`,
  }).from(P)
    .where(and(eq(P.tenantId, ctx.tenantId), eq(P.buildingId, buildingId), eq(P.account, 'fund'), gte(P.bookedAt, from), lt(P.bookedAt, to)))
    .groupBy(P.fund, P.kind, P.refType);
  return rows.map((r) => ({
    fund: r.fund as ReportFund, kind: r.kind as ReportPostingKind, refType: r.refType,
    inflowMinor: Number(r.inflow), outflowMinor: Number(r.outflow),
  }));
}

/** Expenses paid inside the window, voided ones left out, with the supplier's name resolved. */
async function windowExpenses(db: Db, ctx: TenantContext, buildingId: string, from: Date, to: Date, noSupplier: string): Promise<ReportExpense[]> {
  const rows = await db.select({ e: E, supplierName: S.name }).from(E)
    .leftJoin(S, and(eq(S.id, E.supplierId), eq(S.tenantId, E.tenantId)))
    .where(and(eq(E.tenantId, ctx.tenantId), eq(E.buildingId, buildingId), isNull(E.voidedAt), gte(E.paidAt, from), lt(E.paidAt, to)))
    .orderBy(asc(E.paidAt), asc(E.id));
  return rows.map((r) => ({
    id: r.e.id, fund: r.e.fund as ReportFund, description: r.e.description,
    supplier: r.supplierName ?? r.e.supplierText ?? noSupplier,
    amountMinor: r.e.amountMinor, paidAt: r.e.paidAt.toISOString(),
  }));
}

/** Every owner of the building: what they were billed, what they paid, where they stand (addendum 7). */
async function reportOwners(db: Db, ctx: TenantContext, buildingId: string, from: Date, to: Date): Promise<ReportOwner[]> {
  const units = await db.select({ ownerContactId: U.ownerContactId, label: U.label }).from(U)
    .where(and(eq(U.tenantId, ctx.tenantId), eq(U.buildingId, buildingId)));
  const labels = new Map<string, string[]>();
  for (const u of units) {
    if (!u.ownerContactId) continue;
    const list = labels.get(u.ownerContactId) ?? [];
    list.push(u.label);
    labels.set(u.ownerContactId, list);
  }
  const contactIds = [...labels.keys()];
  if (contactIds.length === 0) return [];
  const owned = and(eq(P.tenantId, ctx.tenantId), eq(P.buildingId, buildingId), eq(P.account, 'owner'), inArray(P.contactId, contactIds));
  const [contacts, inWindow, atEnd] = await Promise.all([
    db.select({ id: C.id, firstName: C.firstName, lastName: C.lastName }).from(C)
      .where(and(eq(C.tenantId, ctx.tenantId), inArray(C.id, contactIds))),
    db.select({
      contactId: P.contactId,
      billed: sql<string>`coalesce(sum(case when ${P.kind} = 'charge' then ${P.amountMinor} else 0 end), 0)`,
      // A payment posts a negative to the owner and its void posts the same amount back, so negating
      // both ref types nets a voided payment to exactly zero collected.
      collected: sql<string>`coalesce(-sum(case when ${P.refType} in ('payment', 'payment_void') then ${P.amountMinor} else 0 end), 0)`,
    }).from(P).where(and(owned, gte(P.bookedAt, from), lt(P.bookedAt, to))).groupBy(P.contactId),
    db.select({ contactId: P.contactId, total: sql<string>`coalesce(sum(${P.amountMinor}), 0)` })
      .from(P).where(and(owned, lt(P.bookedAt, to))).groupBy(P.contactId),
  ]);
  const billed = new Map(inWindow.map((r) => [r.contactId!, Number(r.billed)]));
  const collected = new Map(inWindow.map((r) => [r.contactId!, Number(r.collected)]));
  const balance = new Map(atEnd.map((r) => [r.contactId!, Number(r.total)]));
  return contacts.map((c) => ({
    contactId: c.id,
    name: `${c.firstName} ${c.lastName}`.trim(),
    unitLabels: (labels.get(c.id) ?? []).slice().sort((x, y) => x.localeCompare(y)),
    billedMinor: billed.get(c.id) ?? 0,
    collectedMinor: collected.get(c.id) ?? 0,
    balanceMinor: balance.get(c.id) ?? 0,
  }));
}

/**
 * Art. 28 reminders that actually reached an owner in the window. `coalesce(sent_at, created_at)` is
 * the same expression `priorRemindersByOwner` reads, so a letter created in December and printed in
 * January is counted once, in the year it was created.
 */
async function remindersSent(db: Db, ctx: TenantContext, buildingId: string, from: Date, to: Date): Promise<number> {
  const [row] = await db.select({ n: count() }).from(R).where(and(
    eq(R.tenantId, ctx.tenantId), eq(R.buildingId, buildingId), inArray(R.status, ['sent', 'printed']),
    sql`coalesce(${R.sentAt}, ${R.createdAt}) >= ${from.toISOString()}::timestamptz`,
    sql`coalesce(${R.sentAt}, ${R.createdAt}) < ${to.toISOString()}::timestamptz`,
  ));
  return Number(row?.n ?? 0);
}

/** Art. 37 assemblies actually held in the window, oldest first, with how much each decided. */
async function assembliesHeld(db: Db, ctx: TenantContext, buildingId: string, from: Date, to: Date): Promise<ReportAssembly[]> {
  // "assemblies"."id" is hard-coded for the same reason as in resources/assemblies/repo.ts: drizzle
  // renders single-table select columns unqualified inside raw sql, so a bare `id` would bind wrong.
  const rows = await db.select({
    heldAt: AS.heldAt,
    decisionCount: sql<number>`(select count(*) from ${AD} d where d.assembly_id = "assemblies"."id" and d.tenant_id = ${ctx.tenantId})`.mapWith(Number),
  }).from(AS)
    .where(and(eq(AS.tenantId, ctx.tenantId), eq(AS.buildingId, buildingId), eq(AS.status, 'held'), gte(AS.heldAt, from), lt(AS.heldAt, to)))
    .orderBy(asc(AS.heldAt));
  return rows.map((r) => ({ heldAt: r.heldAt!.toISOString(), decisionCount: r.decisionCount }));
}

/** Everything both reports read. Task 3's handover calls it with its own window and nothing else. */
export async function collectReportInput(
  db: Db, ctx: TenantContext, building: BuildingRow, tenant: TenantRow, pack: CountryPack,
  year: number, from: Date, to: Date,
): Promise<AnnualReportInput> {
  const [opening, movements, expenses, owners, reminders, assemblies, [units]] = await Promise.all([
    openingByFund(db, ctx, building.id, from),
    fundMovements(db, ctx, building.id, from, to),
    windowExpenses(db, ctx, building.id, from, to, pack.labels.reports.noSupplier),
    reportOwners(db, ctx, building.id, from, to),
    remindersSent(db, ctx, building.id, from, to),
    assembliesHeld(db, ctx, building.id, from, to),
    db.select({ n: count() }).from(U).where(and(eq(U.tenantId, ctx.tenantId), eq(U.buildingId, building.id))),
  ]);
  return {
    year,
    window: { from: from.toISOString(), to: to.toISOString() },

/**
 * There is no `reports` table: a filed report is a legal event pointing at a document. The list is

export async function listReports(db: Db, ctx: TenantContext, buildingId: string) {
  await getBuilding(db, ctx, buildingId); // 404 across tenants
  const [rows, documents] = await Promise.all([
    db.select({ e: LE, title: D.title, fileName: D.fileName, sizeBytes: D.sizeBytes }).from(LE)
      .leftJoin(D, and(eq(D.id, LE.refId), eq(D.tenantId, LE.tenantId)))
      .where(and(eq(LE.tenantId, ctx.tenantId), eq(LE.buildingId, buildingId), inArray(LE.kind, [...REPORT_EVENTS])))
      .orderBy(desc(LE.occurredAt), desc(LE.seq)),
    listDocuments(db, ctx, buildingId, 'report'),
  ]);
  return {
    rows: rows.map((r) => ({
      eventId: r.e.id,
      kind: (r.e.kind === 'annual_report_issued' ? 'annual' : 'handover') as 'annual' | 'handover',
      occurredAt: r.e.occurredAt,
      documentId: r.e.refId,
      exportDocumentId: typeof r.e.evidence.exportDocumentId === 'string' ? r.e.evidence.exportDocumentId : null,
      title: r.title ?? '',
      fileName: r.fileName ?? '',
      sizeBytes: Number(r.sizeBytes ?? 0),
      evidence: r.e.evidence,
    })),
    documents: documents.rows,
  };

/**
 * One transaction, PDF included (plan addendum 13): a report row with no file, or an event with no
 * report, would be evidence of nothing. A dead renderer gives 503 and files nothing at all.
 */
export async function issueAnnualReport(db: Db, ctx: TenantContext, buildingId: string, year: number, rt: ReportRuntime) {
  return db.transaction(async (tx) => {
    const { building, tenant, pack, data } = await annualReport(tx, ctx, buildingId, year);
    const createdAt = new Date();
    const html = renderAnnualReportHtml({
      tenant, building, data, labels: pack.labels.reports,
      formatMoney: (minor) => pack.formatMoney(minor), timeZone: tenant.timezone, locale: 'mk', createdAt,
    });
    let pdf: Buffer;
    try {
      pdf = await htmlToPdf(html, rt.pdfBrowserChannel);
    } catch (err) {
      rt.log.warn({ err, buildingId, year }, 'annual report pdf render failed; nothing is filed');
      throw new AppError(503, 'pdf_unavailable', 'PDF rendering is not available on this server');
    }
    const document = await createDocumentFromBuffer(tx, ctx, rt.documents, {
      buildingId, kind: 'report',
      title: `${pack.labels.reports.annualTitle} ${year}`,
      fileName: `godisen-izvestaj-${year}-${buildingId}.pdf`, mime: 'application/pdf', content: pdf,
    });
    try {
      const regular = data.funds.find((f) => f.fund === 'regular')!.closingMinor;
      const reserve = data.funds.find((f) => f.fund === 'reserve')!.closingMinor;
      const event = await recordLegalEvent(tx, ctx, {
        buildingId, kind: 'annual_report_issued', refType: 'document', refId: document.id, occurredAt: createdAt,
        evidence: {
          year, documentId: document.id,
          fundClosing: { regular, reserve },
          debtorsCount: data.debtors.length,
          totalDebtMinor: Number(data.fields.totalDebtMinor ?? 0),
        },
      });
      await writeAudit(tx, ctx, {
        action: 'report.annual', entityType: 'document', entityId: document.id,
        after: { year, documentId: document.id, fields: data.fields },
      });
      return { document, exportDocumentId: null, eventId: event.id, year, fields: data.fields };
    } catch (err) {
      // The document row goes back with the transaction, so its bytes must go too: `createDocument`
      // only cleans up after *its own* failure, and a file with no row is an orphan nothing reaches.
      try {
        await rt.documents.remove(document.storageKey);
      } catch (removeErr) {
        rt.log.warn({ err: removeErr, documentId: document.id }, 'annual report rolled back but its file could not be removed');
      }
      throw err;
    }
  });
}

/** The same rule `rowsToCanonicalCsv` uses: flatten a cell's own newlines, then quote `;` and `"`. */
function cell(value: string): string {
  const flat = value.replace(/\r\n|[\r\n]/g, ' ');
  return /[;"]/.test(flat) ? `"${flat.replace(/"/g, '""')}"` : flat;

function csv(header: string[], rows: (string | number | null)[][]): string {
  const line = (xs: (string | number | null)[]) => xs.map((x) => cell(x === null ? '' : String(x))).join(';');

}

/**
 * Art. 30, one transaction: the report, the export and the event, or none of the three. The archive
 * is built **before** either document is filed, so its index is the documentation as it stood at the
 * handover rather than a list that contains itself (plan addendum 11).
 */
export async function issueHandoverReport(db: Db, ctx: TenantContext, buildingId: string, input: HandoverIssueBody, rt: ReportRuntime) {
  return db.transaction(async (tx) => {
    const { building, tenant, pack, data } = await handoverReport(tx, ctx, buildingId, {
      asOf: input.asOf, bankBalances: input.bankBalances, note: input.note ?? null,
    });
    const createdAt = new Date();
    const html = renderHandoverReportHtml({
      tenant, building, data, labels: pack.labels.reports,
      formatMoney: (minor) => pack.formatMoney(minor), timeZone: tenant.timezone, locale: 'mk', createdAt,
    });
    let pdf: Buffer;
    try {
      pdf = await htmlToPdf(html, rt.pdfBrowserChannel);
    } catch (err) {
      rt.log.warn({ err, buildingId, asOf: input.asOf }, 'handover report pdf render failed; nothing is filed');
      throw new AppError(503, 'pdf_unavailable', 'PDF rendering is not available on this server');
    }
    const zip = await buildHandoverExport(tx, ctx, buildingId, data);
    const title = `${pack.labels.reports.handoverTitle} ${input.asOf}`;
    const filed: { id: string; storageKey: string }[] = [];
    try {
      const document = await createDocumentFromBuffer(tx, ctx, rt.documents, {
        buildingId, kind: 'report', title,
        fileName: `primopredavanje-${input.asOf}-${buildingId}.pdf`, mime: 'application/pdf', content: pdf,
      });
      filed.push(document);
      const exportDocument = await createDocumentFromBuffer(tx, ctx, rt.documents, {
        // `other`, not `report`: the portal shows reports to owners, and the full data export of a
        // building is for the incoming manager, not for a resident (plan addendum 12).
        buildingId, kind: 'other', title: `${title} — податоци`,
        fileName: `primopredavanje-${input.asOf}-${buildingId}.zip`, mime: 'application/zip', content: zip,
      });
      filed.push(exportDocument);
      const event = await recordLegalEvent(tx, ctx, {
        buildingId, kind: 'handover_report_issued', refType: 'document', refId: document.id, occurredAt: createdAt,
        evidence: {
          asOf: input.asOf,
          contractEndsOn: data.fields.contractEndsOn === '' ? null : data.fields.contractEndsOn,
          documentId: document.id,
          exportDocumentId: exportDocument.id,
          ownersCount: data.owners.length,
          totalDebtMinor: Number(data.fields.totalDebtMinor ?? 0),
          bankBalances: { regularMinor: input.bankBalances.regularMinor, reserveMinor: input.bankBalances.reserveMinor },
        },
      });
      await writeAudit(tx, ctx, {
        action: 'report.handover', entityType: 'document', entityId: document.id,
        after: { asOf: input.asOf, documentId: document.id, exportDocumentId: exportDocument.id, fields: data.fields },
      });
      return {
        document, exportDocumentId: exportDocument.id, eventId: event.id,
        year: Number(input.asOf.slice(0, 4)), fields: data.fields,
      };
    } catch (err) {
      // Both rows go back with the transaction, so both files must go too.
      for (const d of filed) {
        try {
          await rt.documents.remove(d.storageKey);
        } catch (removeErr) {
          rt.log.warn({ err: removeErr, documentId: d.id }, 'handover rolled back but its file could not be removed');
        }
      }
      throw err;
    }
  });
}

## Self-review notes

**Spec coverage — Phase 2 §7 (reports), phrase by phrase**

- *"Annual report: for a building and a calendar year"* — `GET|POST /buildings/:id/reports/annual`, the year being the **tenant's** civil year (addendum 8), because every other date rule in domar is already civil and this one must not be the exception.
- *"fund opening/closing balances per fund"* — `AnnualReportData.funds`, one `FundSummary` per fund with `opening/inflow/outflow/closing`, and the invariant `opening + inflow − outflow = closing` asserted in Task 1 on fixtures and in Task 2 against a real ledger.
- *"income by category (charges billed, payments received)"* — `fields.billedMinor` and `fields.collectedMinor`, read off owner postings rather than invoices so opening balances and unbound payments are not lost (addendum 7); `fields.collectionRateBp` is the ratio the manager actually gets asked about. **Four risks called out rather than hidden**

1. **Both PDFs are rendered inside their issuing transaction** (addendum 13). A slow Chrome holds no row lock here — nothing is claimed before the render — but it does hold a connection, and a dead Chrome makes issuing a report impossible rather than merely undocumented. That is the deliberate trade, the same one `holdAssembly` makes: the alternative leaves an `annual_report_issued` event pointing at a document that was never written. The only residue a crash can leave is an unreferenced file under `DATA_DIR`.
2. **`fields` is a `Record<string, string | number>`, so a template typo is not a type error.** That is the price of the single map §7 asks for: `n('billedMinorr')` renders `0` instead of failing to compile. Task 1's whole-map `toEqual` is what makes the key set itself a locked contract, and the templates read every scalar through the `n()`/`s()` helpers so the coercion is in one place.
3. **The report reads the ledger as it is now, not as it was at midnight on 31 December.** A payment back-dated into a closed year changes the figures of a report already filed. Nothing is wrong with that — the filed PDF and its event evidence are immutable, and re-issuing produces a second version (addendum 14) — but a manager comparing a two-year-old PDF with a fresh preview of the same year can legitimately see two different numbers. The versioned list is the answer, and it is why nothing overwrites.
4. **`application/zip` is now a storable mime.** The fence is `NewDocument.allow`, which only `createDocumentFromBuffer` sets; the multipart route never does, and `documents.test.ts` locks that an uploaded zip is refused. If a future upload path is ever written, it must not pass `allow` — the default is the upload list precisely so that forgetting is safe.
